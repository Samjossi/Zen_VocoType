# 服务端系统托盘图标与右键菜单实现计划

## 1. 现象

`Zen_VocoType_Service` 启动后系统托盘**完全没有图标**，用户无法直观获知服务端
状态（加载中 / 就绪 / 错误），也无法从托盘执行任何操作（如切换模型、退出服务）。
对照之下，`Zen_VocoType_Client` 托盘图标、状态色点、右键菜单一应俱全；
旧 `GridChat_Service`（参考代码）也有完整的托盘图标与右键菜单。

## 2. 根因分析（调查结论）

逐文件比对后确认：服务端**从未实现过任何托盘/GUI 代码**，不是图标丢失或
加载失败的 bug，而是功能缺失：

| 检查项 | Client | GridChat_Service（参考） | Zen_VocoType_Service |
|---|---|---|---|
| 托盘源码 | `tray/` 子包（QSystemTrayIcon + QMenu） | `app/tray/`（AppIndicator3 + GTK Menu） | **无**（全仓 grep `pystray\|tray\|QSystemTray` 零命中） |
| GUI 依赖 | PySide6 | python3-gi / AppIndicator3 | **无** |
| 图标资产 | `assets/` 四档 PNG | `asset/` 五档 PNG（icon_32/64/128/256 + icon） | **无**（assets/ 仅有 `selftest_16k.pcm`） |
| 主线程形态 | QApplication 事件循环 | GTK 主循环 | 纯控制台守护进程：`shutdown_event.wait()` 驻留（main.py:101），无 GUI 事件循环 |

**结论**：托盘图标必须依附于主线程的 GUI 事件循环。服务端主线程目前阻塞在
`threading.Event.wait()` 上，即使补图标资产也无宿主可显示。
因此本计划 = 新增托盘子包 + 复制 GridChat 图标资产 + 改造 `main.py` 主线程为
Qt 事件循环（与客户端同技术栈 PySide6）。

## 3. 目标与非目标

### 3.1 目标

1. 服务端启动后托盘显示图标（资产直接复制自 `参考代码/GridChat_Service/asset/`），
   图标右下角色点随状态机变化（色点方案与客户端一致，不重绘整套资产）：
   - 橙「加载中…」（`starting`）→ 绿「就绪」（`ready`）→ 红「错误」（`error`）
2. 右键托盘图标弹出完整菜单（菜单结构见 §4.2(4)，含切换模型子菜单）。
3. **无显示环境自动降级**：headless（无 DISPLAY / 托盘不可用）时按现状纯控制台
   运行，托盘为可选增强而非启动前提，不破坏现有 e2e 测试与服务器部署形态。
4. 托盘「退出服务」与 SIGTERM 走**同一条退出路径**（单一出处，禁止两套关闭逻辑）。

### 3.2 非目标

- 不改协议、不改 `server.py` / `state.py` 状态机定义、不改客户端任何代码
- 不做托盘通知气泡（参考代码有 NotificationManager，本计划不引入；切换失败记日志，
  如需桌面通知后续单独立项）
- 不做打包（PyInstaller）适配验证（icon_loader 预留 `_MEIPASS` 分支即可）
- 不引入 GTK/AppIndicator 技术栈（参考代码所用）——与客户端统一用 PySide6

## 4. 方案设计

### 4.1 总体架构

```
主线程                          模型加载线程                Socket accept 线程
──────                          ────────────                ────────────────
QApplication
ServiceTray（QTimer 500ms 轮询
  ctx.state / worker.switching   mark_ready/mark_error ─┐     （不变）
  → 刷新图标色与菜单文本）                                │（线程安全，持锁）
                                                       ▼
信号处理器(SIGTERM/SIGINT) ──► shutdown_event.set()   ServiceState
托盘「退出服务」         ──► shutdown_event.set()     （轮询读取，无回调侵入）
QTimer 200ms 检查 shutdown_event ──► app.quit() ──► 退出序列（不变）

托盘「切换模型」──► 临时 Python 线程 ──► ctx.worker.submit_switch(name)
                                       （worker 队列内与推理互斥，worker.py:104 现成入口；
                                        不在 Qt 主线程阻塞等待——submit 最长阻塞 60s 会冻结托盘）
```

**关键决策：状态同步用 QTimer 轮询而非回调/信号。**

- `ServiceState` 读写已持锁，`worker.switching` 是 `threading.Event`，轮询天然线程安全；
- 不在 `state.py` / `worker.py` 里引入 Qt Signal（核心对象零 GUI 依赖，可单测）；
- 500ms 轮询开销可忽略，状态转换人感知无延迟。

**关键决策：Qt 事件循环替换 `shutdown_event.wait()`，但退出序列一行不改。**

- 信号处理器逻辑不变（仅 `shutdown_event.set()`）；
- 一个 200ms QTimer 检查 `shutdown_event.is_set()` → `app.quit()`；
- `app.exec()` 返回后，main.py 现有退出序列（server.shutdown → worker.stop →
  model_manager.release → lock.release）原样执行；
- 托盘「退出服务」菜单 = `shutdown_event.set()`，与 SIGTERM 汇流。

```python
def main() -> int:
    ...                                  # 配置/日志/单实例锁/启动 server/加载线程：全部不变

    tray = _create_tray_if_available(settings, ctx, shutdown_event)  # 可能为 None
```

```python
def _create_tray_if_available(settings, ctx, shutdown_event) -> ServiceTray | None:
    """托盘创建（可选增强，任何失败降级为无托盘，不阻断服务）。"""
    if not settings.tray_enabled:
        logger.info("配置 tray_enabled=false，纯控制台模式运行")
        return None
    if not os.environ.get("DISPLAY") and not os.environ.get("WAYLAND_DISPLAY"):
        logger.warning("无显示环境（headless），托盘降级为纯控制台模式")
        return None
    try:
        from PySide6.QtWidgets import QApplication, QSystemTrayIcon
        app = QApplication(sys.argv)          # 必须在主线程
        app.setQuitOnLastWindowClosed(False)  # 🔴 无窗口应用，防意外退出
        if not QSystemTrayIcon.isSystemTrayAvailable():
            logger.warning("系统托盘不可用，降级为纯控制台模式")
            return None
        tray = ServiceTray(ctx, poll_interval_ms=settings.tray_poll_interval_ms)
        tray.quit_requested.connect(shutdown_event.set)   # 与 SIGTERM 汇流
        tray.show()
        return tray
    except Exception:
        logger.exception("托盘初始化失败，降级为纯控制台模式（服务不受影响）")
        return None

def _run_with_tray(tray, shutdown_event) -> None:
    """Qt 事件循环驻留；200ms 检查停服信号 → quit → 返回后走统一退出序列。"""
    from PySide6.QtCore import QTimer
    from PySide6.QtWidgets import QApplication
    watchdog = QTimer()
    watchdog.setInterval(200)
    watchdog.timeout.connect(
        lambda: QApplication.quit() if shutdown_event.is_set() else None
    )
    watchdog.start()
    QApplication.exec()
```

- 🔴 顺序敏感红线：`MODELSCOPE_CACHE` 硬设置仍保持 main.py 第一行位置
  （test_main_env_order.py 固化），PySide6 的 import 一律放函数体内延迟导入，
  严禁提升到模块顶部；
- 信号处理器保持同步原语（`Event.set()`），**不在信号处理器里直接调 Qt API**；
- `test_t28_e2e.py` 以 `stdout/stderr=DEVNULL` 子进程方式起服务端：CI 无
  DISPLAY 时自动走降级分支，e2e 不受影响；
- `QApplication` 单例持有：`tray` 返回值不携带 app 引用时，在 main 内以局部变量
  保持 `app` 存活至 `exec()` 结束（实现时留意，防 GC 回收）。

| 风险 | 缓解 |
|---|---|
| PySide6 引入拖慢服务端冷启动 | import 延迟到 `_create_tray_if_available` 内；headless 降级路径完全不 import Qt |
| Qt 事件循环改造破坏退出时序 | 退出序列代码一行不动；仅「驻留方式」从 `Event.wait()` 换为 `exec()`+watchdog；e2e 回归 |
| 托盘切换模型阻塞冻结托盘 | 🔴 `submit_switch` 最长阻塞 60s，必须放临时 Python 线程调用；切换期间子菜单禁用 |
| headless CI 起 QApplication 崩溃 | DISPLAY/WAYLAND_DISPLAY 预检 + try/except 双重兜底；测试用 offscreen |
| 复制相对路径解析恶习 | 只复制 PNG 资产；路径解析沿用客户端 `__file__` 双环境方案，禁止相对 cwd |
| 托盘切换与客户端 model_switch 并发 | 二者统一经 worker 队列串行（worker.py 选型四），天然互斥，无需额外锁 |

## 7. 审阅结论（2026-07-22 09:02 全部裁决，计划定稿）

1. **菜单结构**：定稿为六项「版本 → 状态 → 当前模型 → 切换模型► → 打开日志目录 →
   退出服务」。🔴 **明确不做「查看日志（文本查看器）」**；「重新加载配置」同样不做，
   v1 保持精简。
2. **图标资产**：按裁决直接复制 GridChat_Service/asset 五档 PNG。两托盘图标
   **风格接近但图形完全不同**，并排可区分，无需二次设计。
3. **依赖代价**：服务端引入 PySide6 **可接受**，不采用 GTK/AppIndicator3 备选，
   与客户端技术栈保持一致。
