# 客户端托盘「修改快捷键」与持久化实现计划

## 1. 背景与现状

客户端全局热键当前为**纯静态配置**：`config.py` 的 `Settings.hotkey`
（默认 `<ctrl>+<alt>+o`），启动时 `app.py:107` 解析一次、
`PynputBackend` 监听至终。用户想换快捷键只能手工编辑 `config.yaml`，
且打包形态（AppImage 只读挂载点）下包内 `config.yaml` 根本不可写。

用户诉求：托盘右键菜单增加「修改快捷键」入口，图形化捕获新快捷键，
**长久化保存**（重启客户端后仍然生效）。

### 关键存量资产（调研结论，本计划大量复用）

| 资产 | 位置 | 本计划用途 |
|---|---|---|
| 用户配置文件层 | 契约库 `zen_vocotype_protocol.user_config`（阶段 4 T4.1b） | **持久化的唯一合法落点**：`set_user_config_value("hotkey", expr)` 原子写入 `$XDG_CONFIG_HOME/zen_vocotype/user_config.yaml`；🔴 禁止写包内 `config.yaml`（AppImage 只读挂载点） |
| 配置源链 | 契约库 `settings.py:settings_customise_sources` | 用户配置文件已在链中（优先级：环境变量 > **用户配置文件** > 包内 config.yaml > 默认值），写入后**重启自动生效，零额外加载代码** |
| 表达式解析校验 | `hotkey/combo.py:parse_hotkey` | 新快捷键入库前的合法性校验（解析逻辑单一出处，禁止两处漂移） |
| 热键后端 | `hotkey/pynput_backend.py:PynputBackend`（start/stop 生命周期完整） | 热切换 = stop 旧实例 → 新 combo 建实例 → start |
| 托盘菜单 | `tray/tray.py:ClientTray`（QMenu 结构 + 信号外抛模式） | 新增菜单项与 `hotkey_change_requested` 信号，沿用「托盘零业务逻辑」边界 |

## 2. 目标与非目标

### 2.1 目标

1. 托盘右键菜单新增「修改快捷键…」项，点击弹出**按键捕获对话框**：
   用户直接按下目标组合键，对话框实时回显，确认后生效。
2. 新快捷键**立即热切换**（不重启客户端）：旧监听器停止，新组合键
   即换即用；托盘菜单同步显示当前快捷键。
3. 新快捷键**持久化**：经契约库 `set_user_config_value` 写入用户配置
   文件，重启后自动生效（配置源链现成）。
4. 非法输入（无法解析、主键缺失、未支持的按键）在对话框内即时拦截，
   给出明确提示，🔴 禁止落盘非法表达式导致下次启动 `validate_startup` 崩溃。

### 2.2 非目标

- 不改协议库、不改服务端/启动器任何代码
- 不做多组快捷键/情景配置，单一热键
- 不做快捷键冲突检测（系统级占用无法可靠探测；文档提示用户自查，
  README 保留本机已占用键警示）
- 不做「恢复默认快捷键」单独菜单项（对话框内提供「恢复默认」按钮即可）
- 不改 `validate_startup` 启动校验逻辑（新值入库前已在对话框校验过，
  启动期校验保持不变作为兜底）

## 3. 方案设计

### 3.1 总体流程

```
托盘「修改快捷键…」
      │  hotkey_change_requested 信号
      ▼
app.py:_on_change_hotkey()（主线程，🔴 全部 GUI 与热键操作收敛主线程）
      │  状态守卫：state != IDLE → 通知「录音/识别中，请稍后」并返回
      ▼
HotkeyCaptureDialog（模态 QDialog，主线程）
      │  捕获 QKeyEvent → Qt→pynput 表达式转换 → 实时回显
      │  确认时 parse_hotkey() 预校验，非法则对话框内报错不放行
      ▼  accepted，取得 expression
app.py:_apply_hotkey(expression)
  ① parse_hotkey(expression) 兜底再校验（单一出处）
  ② set_user_config_value("hotkey", expression)   ← 持久化（先落盘）
  ③ self._hotkey.stop()                            ← 停旧监听
  ④ PynputBackend(new_combo, ...) + start()        ← 起新监听
  ⑤ self._settings.hotkey = expression             ← 内存同步
  ⑥ tray.set_hotkey_label(expression) + 通知「快捷键已更新为 …」
  任一步失败 → 回滚（③④失败恢复原后端；②失败整体放弃），通知用户
```

**顺序决策：先落盘后切换。** 落盘失败（如 XDG 目录不可写）时整体放弃，
运行态快捷键不变——避免「运行态已换、重启后丢失」的知行分裂。

### 3.2 详细改动点

#### (1) 新增 `src/zen_vocotype_client/tray/hotkey_dialog.py`

两部分：**纯转换函数**（可无显示单测）+ 对话框本体。

**a) Qt 按键 → pynput 表达式转换（纯函数，本模块核心）**

```python
def qt_event_to_expression(key: int, modifiers: Qt.KeyboardModifiers) -> str | None:
    """QKeyEvent 的 key/modifiers → pynput 组合键表达式；不支持的按键返回 None。"""
```

- 修饰键映射（固定四项）：`ControlModifier→<ctrl>`、`AltModifier→<alt>`、
  `ShiftModifier→<shift>`、`MetaModifier→<cmd>`；
- 主键映射表 `_QT_TO_PYNPUT`：
  - 字母/数字：`Qt.Key_A…Z / Key_0…9` → 对应字符（小写）；
  - 功能键：`Key_F1…F12` → `<f1>…<f12>`；
  - 常用特殊键：空格 `<space>`、Tab `<tab>`、退格 `<backspace>`、
    方向键 `<up>/<down>/<left>/<right>`、Insert/Delete/Home/End/
    PageUp/PageDown → pynput 同名 `<...>` 键；
  - 其余（含纯修饰键按下、媒体键等）→ `None`（对话框提示不支持）；
- 输出形如 `<ctrl>+<alt>+o`（修饰键按 ctrl/alt/shift/cmd 固定序拼接，
  🔴 与现有配置书写习惯一致，便于用户对照 config.yaml 注释）。

**b) `HotkeyCaptureDialog(QDialog)`**

- 布局：说明标签（「请按下新的快捷键组合，Esc 取消」）+ 大号回显框
  （当前捕获组合的人类可读文本，如 `Ctrl + Alt + O`）+ 按钮行
  （「恢复默认」「确定」（捕获到有效组合前禁用）「取消」）；
- `keyPressEvent`：Esc → reject；纯修饰键 → 回显「<已按下的修饰键> + …」
  等待主键；带主键 → 调 `qt_event_to_expression`，支持则暂存表达式并
  点亮「确定」，不支持则回显「不支持的按键：<QKeySequence 文本>」；
- 「确定」前调用 `parse_hotkey(expression)` 预校验（理论必过——转换函数
  产物天然合法，此为防御性兜底），异常时回显错误不放行；
- 「恢复默认」→ 以默认值 `<ctrl>+<alt>+o` 直接 accept（表达式取
  `Settings.model_fields["hotkey"].default`，🔴 禁止硬编码第二份默认值）；
- 公开属性 `expression: str | None`（accept 后由调用方读取）。

#### (2) `tray/tray.py`：菜单扩展

```
┌─────────────────────────────────────┐
│ Zen_VocoType v<版本>                │ 版本项（禁用态，不变）
├─────────────────────────────────────┤
│ 状态：就绪                           │ 状态行（禁用态，不变）
│ 快捷键：Ctrl+Alt+O                  │ 新增① 热键展示行（禁用态，随切换刷新）
├─────────────────────────────────────┤
│ 修改快捷键…                          │ 新增② 触发捕获对话框
│ 重试连接服务端                       │ （不变）
│ 退出                                │ （不变）
└─────────────────────────────────────┘
```

- `ClientTray` 新增信号 `hotkey_change_requested = Signal()`；
- 新增 `set_hotkey_label(expression: str)`：将 pynput 表达式格式化为
  人类可读文本（`<ctrl>+<alt>+o` → `Ctrl+Alt+O`）刷新展示行；
  格式化函数 `format_hotkey_display(expression)` 放 `hotkey/combo.py`
  （表达式知识单一出处，🔴 禁止在 tray 里另写解析），基于
  `parse_hotkey` 结果组织文本，非法输入原样回显；
- 构造时以当前 `settings.hotkey` 初始化展示行（由 app.py 装配时调用一次）；
- ⚠️ 沿用服务端托盘踩过的 PySide6 GC 陷阱教训：所有 action/submenu 引用
  持久持有在 `self._xxx_action`，测试中不经 `contextMenu().actions()`
  临时包装查找。

#### (3) `app.py`：热切换编排

```python
def _on_change_hotkey(self) -> None:
    """托盘「修改快捷键…」入口（主线程）。"""
    if self._sm.state is not State.IDLE:
        self._notifier.notify(APP_DISPLAY_NAME, "录音/识别进行中，请结束后再修改快捷键",
                              key="hotkey-busy")
        return
    dialog = HotkeyCaptureDialog(current=self._settings.hotkey)
    if dialog.exec() == QDialog.DialogCode.Accepted and dialog.expression:
        self._apply_hotkey(dialog.expression)

def _apply_hotkey(self, expression: str) -> None:
    """校验 → 落盘 → 热切换 → 内存/界面同步；失败回滚并通知。"""
```

`_apply_hotkey` 步骤与回滚矩阵：

| 步骤 | 失败处理 |
|---|---|
| ① `parse_hotkey(expression)` | 通知「快捷键表达式非法」；不变更任何状态 |
| ② `set_user_config_value("hotkey", expression)` | 通知「配置写入失败：…」；运行态保持不变（🔴 禁止先切后写的知行分裂） |
| ③ 旧 backend `stop()` + 新 `PynputBackend(combo, ...).start()` | start 失败 → 尝试恢复原 combo 重建旧后端；恢复也失败 → 通知「热键监听失效，请重启客户端」并置托盘 ERROR |
| ④ `self._settings.hotkey = expression`、`tray.set_hotkey_label(...)`、成功通知 | 不会失败 |

- 新 backend 的 on_press/on_release 仍注册 `self.sig_hotkey_press.emit` /
  `sig_hotkey_release.emit`（回调线程红线不变）；
- `self._hotkey` 属性整体替换引用；旧实例 stop 后无引用被 GC
  （pynput Listener.stop 已 join 线程，无悬挂回调风险）；
- 环境变量警示：`ZEN_VOCOTYPE_CLIENT_HOTKEY` 环境变量优先级**高于**
  用户配置文件。`_apply_hotkey` 开头检测该环境变量存在时，通知追加
  「检测到环境变量 ZEN_VOCOTYPE_CLIENT_HOTKEY，重启后将以其为准」——
  不阻断操作，仅如实告知（🔴 禁止静默失效）。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Qt 按键与 pynput 键名映射不全/错位 | 映射表白名单制：未收录按键明确拒绝（对话框提示），🔴 禁止猜测映射落盘非法值；`parse_hotkey` 二次兜底 |
| 录音/识别中热切换丢失 release 事件卡死状态机 | 入口守卫：仅 IDLE 态允许打开对话框；🔴 禁止忙碌中切键 |
| 写包内 config.yaml（AppImage 只读必失败） | 持久化唯一走契约库 `set_user_config_value`（用户配置文件层），包内文件只读不动 |
| 环境变量优先级高于用户配置文件导致「改了不生效」困惑 | `_apply_hotkey` 检测 `ZEN_VOCOTYPE_CLIENT_HOTKEY` 并通知提醒；README 说明优先级链 |
| 落盘成功但新监听启动失败导致无热键空跑 | 回滚矩阵：恢复原 combo 重建旧后端；恢复失败 → 托盘 ERROR + 明确通知（沿用 HotkeyBackendError 红线，不静默） |
