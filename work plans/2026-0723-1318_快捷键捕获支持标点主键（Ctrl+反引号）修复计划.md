# 快捷键捕获支持标点主键（Ctrl+反引号）修复计划（T36）

## 1. 背景与现状

用户在托盘「修改快捷键…」捕获对话框中按 `Ctrl + `` ` ``（反引号键，即
Ctrl+~ 同键位）时，对话框回显「不支持的按键：`」且「确定」按钮禁用，
无法设置该快捷键。

### 根因（已定位，2026-07-23 调查定案）

`tray/hotkey_dialog.py:_build_main_key_map`（第 49-81 行）构建的主键
**白名单** `_QT_TO_PYNPUT` 只收录了：

- 字母 `A`–`Z`、数字 `0`–`9`
- 功能键 `F1`–`F12`
- 少量特殊键：Space、Tab/Backtab、Backspace、方向键、
  Insert/Delete/Home/End/PageUp/PageDown

**标点符号键一个都未收录**。反引号键（Qt `Key_QuoteLeft`）查表返回
None → `qt_event_to_expression` 返回 None → 对话框第 187-191 行回显
「不支持的按键」并禁用「确定」。

### 关键实证（2026-07-23，项目 venv 实测）

底层链路**完全支持**标点主键，缺口仅在白名单映射这一处：

| 验证项 | 结果 |
|---|---|
| `HotKey.parse` 解析全部 22 个主区标点字符表达式（含 `` ` ``、`~`、`+`、`<`、`\` 等） | 全部通过，无异常 |
| `ComboTracker` 合成事件触发 `<ctrl>+`` ` `` / `<ctrl>+<shift>+~` / `<ctrl>+,` | press/release 均正确产出 |
| `format_hotkey_display("<ctrl>+`")` | 输出 `Ctrl+`` ` ``，正常 |

即：**手写 `user_config.yaml` 配置 ``hotkey: "<ctrl>+`"`` 今天就能用**；
GUI 捕获对话框的 Qt 键 → pynput 键映射表漏掉了标点键，是唯一修复点。

### 存量设计约束（🔴 必须遵守）

- `hotkey_dialog.py` 模块 docstring：**白名单映射，未收录按键明确返回
  None，🔴 禁止猜测映射落盘非法表达式**——修复方式是「扩充白名单」，
  不是「放开任意字符猜测映射」；
- 表达式合法性单一出处在 `hotkey.combo.parse_hotkey`，对话框「确定」前
  已有兜底校验（第 198-211 行），新增映射产物天然受其保护；
- `_canonical_key`（backend.py）字符键按 `char.lower()` 匹配——标点无
  大小写变体，不受影响；Shift 组合的移位字符匹配已实证可行（上表）。

## 2. 目标与非目标

### 2.1 目标

1. 捕获对话框支持主键区全部标点键作为主键：` `` ` `~` `-` `_` `=` `+`
   `[` `]` `{` `}` `\` `|` `;` `:` `'` `"` `,` `<` `.` `>` `/` `?`
   （含 Shift 移位变体键符，Qt 按移位后键符上报）。
2. 新增映射产物全部经 `parse_hotkey` round-trip 测试固化（🔴 白名单
   扩充不等于放松校验，产物合法性仍由单一出处兜底）。
3. `Ctrl + `` ` `` 与 `Ctrl+Shift+~`（用户原始诉求）实机可用：捕获 →
   落盘 → 热切换 → 触发录音全链路验证。
4. README 同步说明支持的主键范围。

### 2.2 非目标

- 不改 `combo.py` / `backend.py` / `pynput_backend.py`（实证无需改动）
- 不支持小键盘区标点（`Key_KP_*`，如小键盘加减乘除）——主键区标点
  先行，小键盘有真实需求时再议
- 不开放 Enter/Return 作为主键（与对话框按钮默认焦点冲突）、Esc 维持
  取消语义不变
- 不做非 US 键盘布局的标点适配（其他布局下同一物理键上报的 Qt 键符
  若不在白名单，维持「不支持」提示，属既有白名单语义）
- 不改「不支持的按键」提示交互本身

## 3. 方案设计

### 3.1 改动点（唯一代码改动）

`tray/hotkey_dialog.py:_build_main_key_map` 的 `mapping.update({...})`
块中追加标点映射段：

```python
    # 主键区标点（含 Shift 移位变体：Qt 按移位后键符上报，
    # 如 Shift+` → Key_AsciiTilde；pynput 解析与 char 匹配已实证，T36）
    mapping.update(
        {
            int(Qt.Key.Key_QuoteLeft): "`",
            int(Qt.Key.Key_AsciiTilde): "~",
            int(Qt.Key.Key_Minus): "-",
            int(Qt.Key.Key_Underscore): "_",
            int(Qt.Key.Key_Equal): "=",
            int(Qt.Key.Key_Plus): "+",
            int(Qt.Key.Key_BracketLeft): "[",
            int(Qt.Key.Key_BracketRight): "]",
            int(Qt.Key.Key_BraceLeft): "{",
            int(Qt.Key.Key_BraceRight): "}",
            int(Qt.Key.Key_Backslash): "\\",
            int(Qt.Key.Key_Bar): "|",
            int(Qt.Key.Key_Semicolon): ";",
            int(Qt.Key.Key_Colon): ":",
            int(Qt.Key.Key_Apostrophe): "'",
            int(Qt.Key.Key_QuoteDbl): '"',
            int(Qt.Key.Key_Comma): ",",
            int(Qt.Key.Key_Less): "<",
            int(Qt.Key.Key_Period): ".",
            int(Qt.Key.Key_Greater): ">",
            int(Qt.Key.Key_Slash): "/",
            int(Qt.Key.Key_Question): "?",
        }
    )
```

设计要点：

- **为何直接映射移位后字符而非按键位归一**：`Ctrl+Shift+`` ` `` 在
  Qt/pynput 两侧都上报移位后字符 `~`，表达式 `<ctrl>+<shift>+~` 两端
  一致、可触发（已实证）；若强行归一为 `` ` `` 则物理事件 char='~'
  永不匹配，组合失效。映射表照实记录 Qt 上报值即可，无需特殊处理；
- **`+` 与 `<` 的特别说明**：`+` 是 pynput 表达式分隔符、`<` 是特殊键
  段定界符，理论上存在解析歧义风险——2026-07-23 在当前锁定版本
  pynput 上实测 `<ctrl>++`、`<ctrl>+<` 均正确解析为字符主键。纳入
  白名单并以 round-trip 测试**固化该行为**，未来 pynput 升级若破坏
  则测试当场报警（见 §5 风险表）；
- **白名单哲学不变**：仍是显式枚举的声明式映射，未收录键（媒体键、
  小键盘、Enter 等）照旧返回 None 并提示「不支持的按键」。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Qt 在部分平台（xcb/Wayland-X11）对 Shift+标点上报**未移位**键符（`Key_QuoteLeft` 而非 `Key_AsciiTilde`），导致 `<ctrl>+<shift>+`` ` `` 表达式物理永不触发 | 实机验证步骤专门覆盖该组合；若复现，在 `qt_event_to_expression` 增加「Shift 按下 + 未移位键符 → 移位字符」解析表（仍为显式枚举，不违反禁止猜测红线），并补对应单测 |
| `+` / `<` 字符与 pynput 表达式语法（分隔符/尖括号定界）冲突，未来 pynput 升级破坏解析 | 当前锁定版本已实测可用；round-trip 参数化测试固化全部 22 字符的解析行为，升级即报警；评审若倾向保守可剔除这两个键（见 §6 确认点 2） |
| 反斜杠/引号字符表达式经 YAML 落盘时转义失真 | 落盘 round-trip 测试覆盖 `"<ctrl>+\\"`、`"<ctrl>+\""`，写入→重载原样复原 |
| 用户误以为「Ctrl+~」= `Ctrl+`` ` ``（不加 Shift）导致设置后触发不了 | README 示例明确区分：`Ctrl+`` ` ``（直接按）与 `Ctrl+Shift+~`（加 Shift）是两个不同快捷键，按对话框实际回显为准 |
| 非 US 布局物理同键位上报白名单外键符，仍提示「不支持」 | 属既有白名单语义，不回归；README 注明按美式布局标点键符收录 |
| 白名单扩充被误读为「放开任意字符」 | 计划与代码注释均重申：扩充的是**显式枚举项**，映射表照实记录 Qt 上报值，未收录键照旧拒绝 |

## 6. 待审阅确认点

1. **覆盖范围**：一次收录主键区全部 22 个标点键符（本计划方案）vs
   仅补 `` ` ``/`~` 满足当前诉求——本计划取前者（映射为纯声明式数据，
   边际成本为零，避免后续逐个补票）。
2. **`+` 与 `<` 是否纳入**：实测可解析可触发，本计划纳入并以
   round-trip 测试固化；若评审认为与 pynput 表达式语法的潜在冲突
   不可接受，剔除这两个键（其余 20 个不受影响）。
3. **移位变体落盘形态**：`Ctrl+Shift+`` ` `` 落盘为 `<ctrl>+<shift>+~`
   （按 Qt 上报的移位键符直录，本计划方案）vs 增加「按物理键位归一」
   别名逻辑——本计划取前者（两端上报一致、零特殊逻辑；归一化反而
   破坏 char 匹配）。
4. **小键盘标点（KP_*）**：本计划不收录；如有需求另行评估。
