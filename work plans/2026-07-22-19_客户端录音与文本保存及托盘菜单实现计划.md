# 客户端录音与识别文本保存及托盘菜单实现计划

## 1. 背景与现状

### 1.1 用户诉求

客户端当前录音、识别、粘贴全流程**零落盘**：PCM 数据在
`app.py:329`（`pcm = self._recorder.stop()`）拿到后即 emit 给网络线程，
识别文本只经剪贴板粘贴且 500ms 后被恢复原剪贴板覆盖。用户要求：

1. 每次录音的音频保存为文件（WAV）；
2. 识别（"转换"）出的结果一并保存（对齐参考实现：同名 `.txt` 文本，
   参考代码中不存在"转换出的音频"，识别产物是文本）；
3. 托盘右键菜单提供相应入口（开关保存、选择保存路径、打开保存文件夹）。

### 1.2 参考实现调研结论（`参考代码/GridChat_Client`）

| 维度 | GridChat 做法 | 可借鉴性 |
|---|---|---|
| 录音保存 | `src/audio_recorder.py:_save_wav()`：帧列表 → 标准库 `wave` 写出 `output_dir/YYYYMMDD_HHMMSS.wav`（16k/16bit/单声道） | ✅ 模式直接可用，但客户端 PCM 已是 bytes，无需 PyAudio 采集层 |
| 结果落盘 | `src/speech_to_text.py:save_transcription_to_file()`：与 wav 同基名 `.txt` 同目录存放 | ✅ 直接沿用 |
| 路径配置 | 托盘菜单「选择录音路径」→ zenity/kdialog/yad 子进程选目录 → 写用户级 `~/.config/grid_chat/settings.json` | ⚠️ 借鉴思路，不照抄实现：客户端是 PySide6，原生 `QFileDialog` 即可，无需三选择器回退链；持久化走契约库 `set_user_config_value` |
| 已知缺陷（避免照抄） | 配置分散三处且 `socket_config.json` 的 `recordings_dir` 与实际生效路径不一致；无「打开录音文件夹」菜单项 | 🔴 客户端必须保证默认值唯一出处 + 实际生效路径一致 |

### 1.3 客户端关键存量资产（本计划大量复用）

| 资产 | 位置 | 本计划用途 |
|---|---|---|
| PCM 获取点 | `app.py:329` `_on_transition` 中 `pcm = self._recorder.stop()` | **WAV 保存注入点**（emit 识别请求之前落盘） |
| 文本获取点 | `app.py:341` `_handle_output(text)` / `_on_recognize_done` | **TXT 保存注入点**（与当前 wav 关联） |
| 音频参数常量 | 契约库 `zen_vocotype_protocol.paths`：`DEFAULT_SAMPLE_RATE=16000 / DEFAULT_SAMPLE_WIDTH=2 / DEFAULT_CHANNELS=1` | 写 WAV 头的唯一出处，🔴 禁止客户端硬编码 |
| 持久化通道 | 契约库 `user_config.set_user_config_value`（app.py:245 已有调用先例） | `recordings_dir` / `save_recordings` 落盘，重启自动生效 |
| 托盘菜单模式 | `tray/tray.py:82-108`：Signal 外抛 + `app.py` 接线，「托盘零业务逻辑」 | 新增菜单项沿用同一边界 |
| 通知复用 | `Notifier.notify(title, message, key=...)`（带去重） | 保存失败/路径已更新等提示 |
| XDG 规范红线 | `config.py:68-69`：可写路径必须落 XDG 用户目录，禁止组件根目录（AppImage 只读挂载） | 默认保存目录必须落 `~/.local/share/zen_vocotype/recordings` |

## 2. 目标与非目标

### 2.1 目标

1. 每次录音停止后，PCM 落盘为 `<保存目录>/YYYYMMDD_HHMMSS.wav`
   （标准库 `wave` 写出，参数取契约库冻结常量）；文件名冲突追加
   `_2`/`_3` 序号兜底。
2. 识别完成后，文本落盘为同基名 `.txt`（与 wav 同目录）；识别失败
   （服务端错误/超时）时 wav 保留、不写 txt，已有 wav 不受影响。
3. 托盘右键菜单新增三项：
   - 「保存录音」勾选项（默认开）：切换是否落盘，立即生效并持久化；
   - 「选择保存路径…」：`QFileDialog.getExistingDirectory` 选目录，
     校验可写后持久化，通知用户；
   - 「打开保存文件夹」：`QDesktopServices.openUrl` 打开当前保存目录。
4. `save_recordings` / `recordings_dir` 持久化到用户配置文件
   （`set_user_config_value`），重启自动生效。
5. 保存失败（目录不可写、磁盘满等）**不阻断**识别-粘贴主流程，
   仅通知告警并记日志。

### 2.2 非目标

- 不做录音文件管理界面（列表/播放/删除），v1 仅落盘 + 打开文件夹
- 不做 MP3/FLAC 等压缩编码（WAV 原始体积可接受：60s ≈ 1.9MB）
- 不做识别历史数据库/检索
- 不改服务端、启动器；契约库仅按 §6 确认点 1 最小新增目录 helper
- 不保存"转换出的音频"（参考实现无此物，识别产物为文本，见 §1.1）

## 3. 方案设计

### 3.1 总体数据流

```
热键松开 → _on_transition（主线程）
   │  pcm = Recorder.stop()
   ▼
RecordingStore.save_wav(pcm) ──失败──▶ 通知告警 + 日志，继续主流程
   │  成功返回 wav_path，存 self._current_wav_path
   ▼
sig_recognize_request.emit(pcm)（原流程不变）
   │
   ▼ 识别完成
_on_recognize_done → _handle_output(text)（原剪贴板流程不变）
   │
   ▼
RecordingStore.save_txt(self._current_wav_path, text)
   ──失败──▶ 通知告警 + 日志（wav 已落盘，不回滚）
```

**顺序决策：先存 wav 后发识别。** wav 是用户原始音频，识别失败时
仍应保留（GridChat 同此语义）；txt 依赖识别结果，只能后写。
`_current_wav_path` 为单实例成员：客户端状态机保证同一时刻仅一路
录音-识别在途（IDLE 才响应热键），无并发竞争。

### 3.2 详细改动点

#### (1) 新增 `src/zen_vocotype_client/storage/recording_store.py`

纯逻辑模块（零 Qt 依赖，可无显示单测）：

```python
class RecordingStore:
    def __init__(self, directory: Path,
                 sample_rate: int, sample_width: int, channels: int): ...
    def save_wav(self, pcm: bytes) -> Path:
        """写 YYYYMMDD_HHMMSS.wav（冲突追加 _2/_3），返回路径；
        目录不存在则创建；失败抛 OSError 由调用方转通知。"""
    def save_txt(self, wav_path: Path, text: str) -> Path:
        """同基名 .txt，utf-8 写出。"""
    def set_directory(self, directory: Path) -> None: ...
```

- 音频参数由 `app.py` 装配时从契约库 `paths` 常量注入，本模块不 import
  契约库（保持纯逻辑、测试零依赖）。
- 空 PCM（极短录音）仍保存（如实记录，不做时长门限——GridChat 同）。

#### (2) `config.py`：`Settings` 新增两字段

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `save_recordings` | bool | `True` | 录音/文本落盘总开关 |
| `recordings_dir` | Path | XDG data 下 `zen_vocotype/recordings`（见 §6 确认点 1） | 保存目录 |

- 校验：`recordings_dir` 必须为绝对路径（对齐 config.yaml 既有红线
  「路径类配置写绝对路径」）；`validate_startup` 增加「目录可创建且
  可写」探测，失败退出码沿用配置类错误 **2**。
- `config.yaml` 增加注释示例（不照抄默认值，保持唯一出处）。

#### (3) `app.py`：装配与接线

- `ClientApp.__init__`：构造 `RecordingStore`（参数取契约库常量 +
  `settings.recordings_dir`），`self._current_wav_path: Path | None = None`。
- `_on_transition`（app.py:329 附近）：拿到 `pcm` 后、emit 前——
  `if settings.save_recordings:` 调 `save_wav`，异常捕获 →
  `Notifier.notify("录音保存失败", ..., key="save_wav")` + 日志，
  `_current_wav_path = None`，**不 return**（主流程继续）。
- `_handle_output`（或 `_on_recognize_done`）：
  `if self._current_wav_path and settings.save_recordings:` 调
  `save_txt`，同样异常隔离；用后清空 `_current_wav_path`。
- 识别失败路径（`_on_recognize_error`）：仅清空 `_current_wav_path`，
  wav 保留。
- 三个菜单信号槽（全部主线程）：
  - `_on_toggle_save(checked)`：`set_user_config_value` 先落盘 →
    内存同步；落盘失败回滚勾选态并通知（沿用 T33「先落盘后切换」顺序）。
  - `_on_choose_dir()`：状态守卫（非 IDLE 提示稍后）→
    `QFileDialog.getExistingDirectory` → 写入临时文件探测可写 →
    落盘 + `store.set_directory` + 通知。
  - `_on_open_dir()`：`QDesktopServices.openUrl(QUrl.fromLocalFile(...))`，
    目录不存在则先创建。

#### (4) `tray/tray.py`：菜单扩展（零业务逻辑）

在「修改快捷键…」之上/之下插入（最终位置见 §6 确认点 2）：

- `QAction("保存录音", checkable=True)`，checked 由 `app.py` 初始化时
  `set_save_checked(settings.save_recordings)` 注入；信号
  `save_toggled(bool)`。
- `QAction("选择保存路径…")` → 信号 `choose_dir_requested`。
- `QAction("打开保存文件夹")` → 信号 `open_dir_requested`。

#### (5) 契约库 `paths.py`（按 §6 确认点 1 的最小新增）

```python
def get_recordings_dir() -> Path:
    """$XDG_DATA_HOME/zen_vocotype/recordings（默认 ~/.local/share/...）"""
```

与既有 `_default_data_dir` / log dir 同模式，作为默认保存目录唯一出处。

## 6. 确认点（默认方案，批准后按此执行）

1. **默认保存目录出处**：默认在契约库 `paths.py` 新增
   `get_recordings_dir()`（与 log dir 同模式，唯一出处原则）。
   备选：客户端本地按 XDG 环境变量计算（不动契约库，但制造第二处
   XDG 解析逻辑）。**默认选前者。**
2. **菜单位置**：三项置于「修改快捷键…」之后、「重试连接服务端」之前，
   并以分隔线与既有功能区分组。
3. **默认开关**：`save_recordings` 默认 **开**（用户诉求即"保存起来"）。
4. **保存内容**：wav + 同名 txt（文本）。用户表述中"转换出来的音频"
   按参考实现实际语义理解为识别结果文本；如确需 TTS 音频则另立计划。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 主线程同步写盘引入卡顿 | 60s WAV ≈1.9MB，写盘毫秒级；txt 为 KB 级，均可接受；不做异步线程（避免新的线程红线） |
| 用户选择不可写目录 | 选目录时临时文件写探测拦截；保存期失败通知告警不阻断 |
| 长期运行磁盘占用 | README 注明保存位置与清理方式；管理界面列为后续候选 |
| 识别失败后 wav 堆积无对应 txt | 语义有意为之（保留原始音频）；txt 缺失即识别失败的可观测信号 |
