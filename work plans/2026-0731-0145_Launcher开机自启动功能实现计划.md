## 1. 目标

为 Zen_VocoType_Launcher 增加「登录桌面环境后自动启动」开关：勾选后，用户下次登录时桌面环境自动拉起 Launcher（Launcher 再按本职编排拉起 Service 与 Client）。

机制照搬指南：维护 `~/.config/autostart/zen-vocotype.desktop`，纯文件操作，无需 root / systemd / IPC；首次运行时清理历史遗留自启动条目（详见 §2.2），保证系统内自启入口唯一。

### 1.1 边界（不做什么）

- 仅 Linux（`is_supported()` 判断，非 Linux 禁用菜单项）
- 🔴 不为 Service / Client 单独做自启动——自启入口唯一为 Launcher，避免三端各自注册、启动顺序失控
- 不做 Windows / macOS（指南 §6 留扩展点，本期不实现）
- 不动现有编排 / 延迟设置 / 组件位置设置逻辑
- 不改 `tools/desktop_entry.py`（T43 安装器）的安装/卸载逻辑——仅与之对齐命名（§2.2）

## 2. 适配分析（指南 → 本项目）

| 指南项 | CopyQ 形态 | Launcher 适配 |
|:---|:---|:---|
| UI 入口 | 设置对话框勾选框 | 托盘菜单**勾选态菜单项**（托盘零业务逻辑红线不变：action 只外抛 Signal） |
| 配置持久化 | `general.autostart`（toml） | `Settings.autostart_enabled: bool = False`，落盘走契约库 `set_user_config_value`（🔴 禁写包内 config.yaml） |
| 双端同步 | 启动时配置 → 系统校验 | 托盘装配层 `LauncherTrayApp.__init__` / `exec()` 早期做一次一致性校验，以配置为准修复 |
| Exec 命令 | AppImage / dev 双模式 | Launcher 同需：`$APPIMAGE` → AppImage 路径；否则 `sys.executable` + 组件根 `main.py`；🔴 打包形态为 onedir（`dist/zen_vocotype_launcher/zen_vocotype_launcher` 可执行文件）需第三档 |
| 原子写入 | 临时文件 + rename | 原样沿用（注意 AGENTS.md 红线：🔴 临时文件不得落系统临时目录——`~/.config/autostart/*.desktop.new` 同目录临时文件，合规） |

### 2.1 Exec 三档优先级（本项目新增 onedir 档）

1. **AppImage**：`$APPIMAGE` 存在且是文件 → `"$APPIMAGE"`
2. **onedir 打包**：`sys.executable` 指向冻结可执行文件（`getattr(sys, "frozen", False)`）→ `"sys.executable"`
3. **开发模式**：`"sys.executable" "组件根/main.py"`（组件根经 `config.COMPONENT_ROOT` 取，单一出处）

### 2.2 命名口径统一与遗留条目清理（2026-07-31 修订新增）

**现状诊断**（2026-07-31 实机确认）：

| 来源 | desktop ID | 位置 | 状态 |
|:---|:---|:---|:---|
| 历史手动条目 | `zen_vocotype`（下划线） | `~/.config/autostart/zen_vocotype.desktop` | 🔴 生效中，`Exec` 指向 `~/AppImages/zen_vocotype_launcher.appimage` |
| T43 安装器（`tools/desktop_entry.py:26` `DESKTOP_ID`） | `zen-vocotype`（连字符） | `~/.config/autostart/zen-vocotype.desktop` | 安装器 `install --autostart` 时写入；卸载恒删 |
| 本计划初稿 | `zen-vocotype-launcher` | — | ❌ 第三套命名，废弃 |

三个 ID 互不知晓：若运行时功能另起新名，历史条目不受管理，登录时多个条目同时触发 → Launcher 被重复拉起，且旧条目固定指向 AppImage 形态，dev/prod 切换后失控。

**统一决策**：

- 🔴 **desktop ID 唯一出处为 `tools/desktop_entry.py` 的 `DESKTOP_ID = "zen-vocotype"`**，运行时 `AutostartManager` 沿用同值（常量独立定义，不跨组件 import——`tools/` 非包内模块）。理由：
  - 与 T43 安装器卸载逻辑对称（`tools/desktop_entry.py:167` 卸载恒删 `autostart/zen-vocotype.desktop`，运行时写入的文件可被一并清除）；
  - 与 T43 安装器写入的自启条目同文件：安装器写的是静态快照，运行时启动校验会按当前形态重写 `Exec`，两者共存无冲突；
  - 菜单条目（`~/.local/share/applications/zen-vocotype.desktop`）与自启条目分属不同目录，同 ID 不冲突。
- **遗留条目清理**：`AutostartManager` 维护 `LEGACY_DESKTOP_IDS = ("zen_vocotype",)`（下划线旧名）。启动装配层做一致性校验前先调用 `remove_legacy_desktop_files()` 删除这些遗留文件，记日志。删除是幂等的，不影响 `zen-vocotype.desktop` 本体。
  - 清理只针对 **autostart 目录** 的遗留条目；`~/.local/share/applications/` 下的菜单条目（如 `zen_vocotype_launcher.desktop`）不在本功能范围，不动。

## 5. 风险与注意

- **登录瞬间负载**：Service 模型加载重，保留 `X-GNOME-Autostart-Delay=3`；用户可再叠加托盘既有「服务端启动延迟」
- **托盘回退场景**：自启动拉起时若无显示环境，Launcher 回退一次性 CLI（既有行为）——自启动功能本身不受影响
- **dev / prod 并存**：desktop 文件只有一份，`Exec` 指向最后写入时的运行形态；dev 模式改动后切回 prod 需在 prod 下重启一次 Launcher 触发一致性校验重写（可接受，文档注明）
- **与 T43 安装器的写序**：安装器 `install --autostart` 写的是静态快照（Exec 指向安装时 AppImage）；运行时每次启动按当前形态重写 `Exec`，后写覆盖先写，语义一致无冲突。卸载时安装器恒删该文件，与运行时 `remove_desktop_file()` 行为等价
- **遗留清理的边界**：仅清理 autostart 目录下 `LEGACY_DESKTOP_IDS` 列出的文件，白名单制——不扫描、不猜测其他命名，避免误删用户自有条目
- **原子写临时文件位置**：`~/.config/autostart/*.desktop.new`（同目录），不触 AGENTS.md 系统临时目录红线
