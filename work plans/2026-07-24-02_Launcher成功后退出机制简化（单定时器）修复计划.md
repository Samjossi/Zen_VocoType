# Launcher 成功后退出机制简化修复计划（T44：单定时器 + 拆除菜单暂停）

## 1. 背景与现状

### 1.1 直接动因：菜单暂停机制在 GNOME 上机制性失效（已诊断定案）

T40 设计的「成功后自动退出」由**两套机制**组成：8 秒倒计时（可被「菜单/
对话框打开」暂停）+ 60 秒强制退出兜底（不可暂停）。2026-07-24 凌晨实机
诊断证实**暂停判据在 GNOME SNI 下根本不可用**：

- launcher.log 全量统计：**「倒计时已暂停」28 次、「倒计时恢复」0 次、
  兜底触发 14 次**——用户不可能 28 次打开菜单不关闭；
- 每次暂停精确落在编排完成瞬间（倒计时启动后 5ms）；
- 根因：编排完成时 `set_status`/`set_progress` 修改菜单项 → Qt DBusMenu
  广播 `LayoutUpdated` → GNOME Shell（AppIndicator 扩展）**主动回调
  `AboutToShow` 预取菜单**（预渲染行为，非用户操作）→ `QMenu.aboutToShow`
  → `menu_opened` → 暂停计数 +1；菜单从未真实打开，`menu_closed` 永不
  配对 → 倒计时永久冻结 → 每次成功路径全靠 60 秒兜底退出；
- Qt 层**无法区分**「Shell 预取」与「用户真打开」——该功能在 GNOME 上
  无解（KDE 等原生 X11 托盘后端才按设计工作）。

### 1.2 历史包袱：倒计时功能自身引来过事故

15:10 报告实机事故：用户误设 `auto_exit_delay_s=0` → 幂等命中秒退 →
GNOME 托盘图标异步注册未完成 →「无托盘」错觉。该事故类随倒计时功能
一并移除。

### 1.3 现状机制盘点（待拆除/改造对象）

| 机制 | 位置 | 处置 |
|---|---|---|
| 8 秒倒计时（`auto_exit_delay_s`，ge=4/le=60）+ 逐秒进度刷新 | `config.py`、`app.py:_start_auto_exit/_on_auto_exit_tick` | **拆除**，由单一定时器取代（倒计时**显示**保留） |
| 菜单开合暂停（`menu_opened/menu_closed` ← `aboutToShow/aboutToHide`） | `tray/tray.py:133-135`、`app.py:_pause_auto_exit/_resume_auto_exit` | **拆除**（GNOME 上假阳性 100%，无解） |
| 暂停计数 + 挂起标记（`_exit_pause_count`/`_exit_pending_immediate`） | `app.py` | **拆除** |
| 60 秒强制退出兜底（`_FORCE_EXIT_AFTER_S`，硬编码不可配） | `app.py:_start_force_exit/_on_force_exit` | **升格为主机制**，改为用户可配（默认 60、下限 30） |
| 设置对话框显式暂停（`_ask_int`/`_pick_binary` try/finally） | `app.py` | **保留**（不依赖 SNI 事件，可靠；防改设置到一半被退出） |
| 失败路径托盘永驻（防静默失败红线） | `app.py:_on_finished` | **不动** |

### 1.4 迁移安全性（已实证，2026-07-24）

- 契约库 `_UserConfigSettingsSource`（settings.py:71）**只拾取
  `model_fields` 已声明字段**——Settings 删除 `auto_exit_delay_s` 后，
  用户配置文件中的旧键（实机现存 `auto_exit_delay_s: 8`）**自动忽略**，
  无校验失败风险；
- 包内 `config.yaml` 中该键为注释态（无实际键），BaseSettings 默认
  `extra=forbid` 不触达；
- 🔴 结论：**换新字段名（`exit_after_success_s`）是零风险迁移路径**。
- 旧键虽无害但会永久滞留——实施时附带**单行清理**（见 §4 步骤 0）：
  仅删 `~/.config/zen_vocotype/user_config.yaml` 中 `auto_exit_delay_s: 8`
  一行（用户已授权本次访问项目外该文件；🔴 其余键 `hotkey`/
  `service_start_delay_s`/`client_start_interval_s`/`paste_restore_delay_ms`
  严禁触碰；该文件为三组件共享，🔴 禁止删整个文件）。

## 2. 目标与非目标

### 2.1 目标

1. 成功后退出收敛为**单一定时器**：编排成功 → 进度行逐秒倒计时
   「✓ 启动完成，启动器将于 N 秒后退出」→ 到点退出；N 用户可配
   （`exit_after_success_s`，默认 60、范围 30~300，托盘菜单可设、
   持久化、环境变量覆盖警示——T40 模板不变）；
2. **彻底拆除**菜单开合暂停链路（托盘信号、装配层连接、暂停计数、
   挂起标记）——GNOME 假阳性清零；
3. **保留**设置对话框显式暂停（模态对话框弹出期间定时器停走，关闭后
   从剩余秒数续走）；
4. 失败路径托盘永驻语义不变；状态重检轮询（慢启动客户端锁文件等待）
   不变；
5. 旧配置键零感知迁移（§1.4 已实证）。

### 2.2 非目标

- 不改 Service/Client 托盘的任何信号与行为；
- 不改 `service_start_delay_s` / `client_start_interval_s` / T42
  `client_settle_timeout_s` 三个既有字段；
- 不试图区分 SNI 预取与真实菜单打开（Qt 层无解，已定论）；
- 不引入「0 = 永不退出」选项（失败路径已覆盖驻留需求；成功路径必须
  退出是选型七「一次性编排器」的根基）；
- 不动编排/发现/就绪等待任何逻辑（改动严格限制在退出机制）。

## 3. 方案设计

### 3.1 配置层（`config.py`）

```python
#: 成功后退出秒数（T44 单一定时器）：编排成功后托盘停留观察窗口，
#: 到点无条件退出（🔴 失败路径不启动本定时器——防静默失败红线）。
#: 默认 60 秒、下限 30 秒（GNOME SNI 托盘图标异步注册只需 ~4 秒，
#: 30 秒下限对「图标必然可见」有 7 倍余量；2026-07-24 拆除菜单暂停
#: 机制后，本字段是成功后退出的唯一控制项，取代旧 auto_exit_delay_s
#: + 60 秒硬编码兜底的双机制）。设置对话框打开期间倒计时暂停
#: （显式 try/finally，不依赖 SNI 菜单事件——该事件在 GNOME 上不可靠）
exit_after_success_s: float = Field(default=60.0, ge=30, le=300)
```

- 删除 `auto_exit_delay_s` 字段与 `AUTO_EXIT_DELAY_ENV_VAR` 常量；
- 新增 `EXIT_AFTER_SUCCESS_ENV_VAR = "ZEN_VOCOTYPE_LAUNCHER_EXIT_AFTER_SUCCESS_S"`；
- `config.yaml` 注释块同步（旧行替换为新字段说明）。

### 3.2 装配层（`app.py`）

**拆除**（约 -120 行）：`_auto_exit_timer`/`_auto_exit_remaining`/
`_exit_pause_count`/`_exit_pending_immediate`/`_start_auto_exit`/
`_stop_auto_exit`/`_on_auto_exit_tick`/`_pause_auto_exit`/
`_resume_auto_exit`/`_force_exit_timer`/`_start_force_exit`/`_on_force_exit`/
`_FORCE_EXIT_AFTER_S`/`_AUTO_EXIT_UI_MIN`/`_AUTO_EXIT_UI_MAX`；
`_connect_signals` 中 `menu_opened/menu_closed` 两条连接。

**新增**（约 +50 行）：

```python
#: 成功后退出定时器轮询间隔（秒）：逐秒刷新倒计时显示
_EXIT_TICK_S = 1000  # ms

# __init__：
self._exit_remaining = 0
self._exit_timer = QTimer(self._qapp)
self._exit_timer.setInterval(_EXIT_TICK_S)
self._exit_timer.timeout.connect(self._on_exit_tick)

# 成功路径（_on_finished 中，exit_code==SUCCESS 分支）：
self._start_exit_countdown()
# （状态重检轮询逻辑原样保留）

def _start_exit_countdown(self) -> None:
    self._exit_remaining = int(self._settings.exit_after_success_s + 0.999)
    self._tray.set_progress(
        f"✓ 启动完成，启动器将于 {self._exit_remaining} 秒后退出"
    )
    self._exit_timer.start()

def _stop_exit_countdown(self) -> None:  # 「立即启动」重试时撤销
    self._exit_timer.stop()
    self._exit_remaining = 0

def _on_exit_tick(self) -> None:
    self._exit_remaining -= 1
    if self._exit_remaining <= 0:
        self._exit_timer.stop()
        logger.info("成功后退出定时器到点（{} 秒），Launcher 退出（两端不受影响）",
                    self._settings.exit_after_success_s)
        self._qapp.quit()
    else:
        self._tray.set_progress(
            f"✓ 启动完成，启动器将于 {self._exit_remaining} 秒后退出"
        )

# 对话框显式暂停（_ask_int/_pick_binary 内）：
def _pause_exit_timer(self) -> bool:
    """设置对话框弹出期间停走（返回是否原本在走，供恢复判断）。"""
    if self._exit_timer.isActive():
        self._exit_timer.stop()
        return True
    return False

def _resume_exit_timer(self, was_active: bool) -> None:
    if was_active:
        self._exit_timer.start()  # interval 不变，从剩余秒数续走
```

- `_on_start`（重试）：`self._stop_exit_countdown()` + 重检轮询停止
  （原有行保留）；
- `_ask_int`/`_pick_binary`：try 前 `was = self._pause_exit_timer()`，
  finally 中 `self._resume_exit_timer(was)`；
- 菜单项文案与范围：`成功后自动退出（N 秒）…` → 对话框
  「编排成功后托盘停留多少秒自动退出（30~300）：」；
- 环境变量覆盖警示沿用 `_env_override_suffix(EXIT_AFTER_SUCCESS_ENV_VAR)`；
- `_notify`/`_on_quit`/状态重检：零改动。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 旧 `auto_exit_delay_s` 残留配置导致启动失败 | §1.4 已实证零风险（用户配置源只拾取声明字段）；迁移用例固化 |
| 用户习惯 8 秒快退，60 秒驻留嫌久 | 菜单项可调（30~300）；进度行逐秒倒数保持可预期性；驻留不占资源且托盘可见性更充分（15:10 事故类根治） |
| 对话框打开时定时器停走，用户长时间不关对话框 → 启动器永驻 | 语义可接受（模态对话框开着 = 用户正在交互）；相比旧设计失去的只是「60 秒强制兜底杀对话框」这一粗暴保护，换得机制单一 |
| 拆除菜单暂停后，用户真打开右键菜单看到一半启动器退出 | 菜单只是只读状态展示 + 设置入口；60 秒窗口足够查看；设置动作均经对话框（有显式暂停保护） |
| 测试改写面大（~15 旧用例） | 旧用例语义随机制一并作废，非「丢失覆盖」；新用例矩阵按 §3.4 逐条映射 |

**实机验证清单**（步骤 7）：

1. 重启或手动执行 Launcher → 编排成功 → 进度行逐秒倒数 → 60 秒到点
   自行退出（日志「成功后退出定时器到点」）；
2. 倒计时期间打开「成功后自动退出…」对话框停留 >10 秒关闭 → 倒计时
   从剩余秒数续走（不重置、不漏走）；
3. 改为 30 秒（下限）→ 重启 Launcher 验证生效且持久化；
4. 托盘右键菜单开合数次 → 日志**零**「暂停」类记录（假阳性清零）；
5. 两端已在运行时执行 Launcher（幂等秒完）→ 60 秒倒计时可见、托盘
   图标全程可见（15:10 事故类不复发）。

## 6. 待审阅确认点

1. **上限取 300 秒**：与其他延迟字段（`service_start_delay_s` 等）的
   le=300 对齐；若希望允许更长驻留可放宽至 600。
2. **对话框暂停保留**（本计划方案）vs 一并拆除（定时器绝对不可暂停，
   机制最简但改设置到 60 秒边界会被踢出对话框）——本计划取前者
   （可靠性不依赖 SNI，成本仅两行）。
3. **进度行倒计时显示保留**（逐秒刷新）vs 静态文本（「启动完成，将于
   60 秒后退出」不逐秒）——本计划取前者（可预期性，零额外机制）。
4. **旧菜单项文案沿用**「成功后自动退出（N 秒）…」（用户已熟悉）vs
   改名「成功后退出时间（N 秒）…」——本计划取前者。
