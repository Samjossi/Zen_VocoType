## 1. 目标

将 Zen_VocoType 三组件（Protocol / Service / Launcher）重写为 MoonBit，与保留的 Python Client 组成完整可用的 Linux 桌面语音输入系统，达到现有 Python 版功能 parity，作为 2026 MoonBit 大赛参赛作品。

- 🔴 **大部分代码为 MoonBit**：新增代码中 MoonBit 占比目标 ≥ 80%（按行数统计，`moonbit/` 目录 vs 本期新增 Python 代码——本期 Python 侧目标为零新增）
- 🔴 **平台锁定 Linux**：Windows 支持与 MoonBit 重写是两个正交问题，本期均不做 Windows（MoonBit native 后端 Windows 支持尚不完善，官方明确 stacktrace 未支持 Windows 平台）
- 🔴 **功能 parity**：以现有 Python 版为行为基线，不引入新功能、不裁剪用户可感知能力（引擎裁剪除外，见 §2.2）

### 1.1 边界（不做什么）

- 不做 Windows / macOS 平台适配
- 不重写 `Zen_VocoType_Client/`（托盘 PySide6 / 全局热键 pynput / 录音 sounddevice / 粘贴——桌面集成生态缺口全集中于此，复用现有 Python 实现）
- 不在 MoonBit 内 FFI 直嵌 llama.cpp（推理继续 spawn 现有 `Zen_VocoType_Service/bin/llama-funasr-cli` 子进程，MoonBit 只做编排）
- 不动打包体系 `tools/`（AppImage / 桌面入口安装器本期不覆盖 MoonBit 产物的打包，开发态交付优先）
- 不改 Unix Socket 协议契约（帧格式 / action / 错误码 / 路径约定保持原样，协议是跨语言对接的根基）

## 2. 策略：组件级替换

### 2.1 架构依据

项目四组件**仅经 Unix Socket 协议协作，组件间禁止相对路径 import、零代码耦合**（协议契约见 `协议/` 目录与 `Zen_VocoType_Protocol/`）。这意味着可按组件粒度整体替换：MoonBit 实现的 Service/Launcher 只要遵守同一协议，Python Client 无感知对接，无需发明任何新的桥接机制。这是本计划成立的根本前提。

### 2.2 组件去向

| 组件 | 去向 | 理由 |
|:---|:---|:---|
| `Zen_VocoType_Protocol/` | → MoonBit 全部重写 | 纯 stdlib 契约库（帧格式 / action / 错误码 / 路径唯一出处 / 配置链行为），零生态依赖；MoonBit ADT + 模式匹配写编解码质量更高 |
| `Zen_VocoType_Service/` | → MoonBit 全部重写 | 重写主战场：模型注册表 / 原子切换 / 推理编排 / Socket 服务端 / 单实例锁，均为纯逻辑；推理 spawn 现有 `llama-funasr-cli` 二进制 |
| `Zen_VocoType_Launcher/` | → MoonBit 全部重写 | 拉起编排 / 两阶段就绪等待 / 幂等识别（`/proc`）/ 进程组回收（`killpg`）均为纯逻辑 + 少量 POSIX 调用，Linux 下用薄 C FFI 或直接读文件即可 |
| `Zen_VocoType_Client/` | **保留 Python，零改动** | 桌面集成生态缺口集中地，现有实现直接复用 |

### 2.3 引擎裁剪决策

| 引擎 | Python 版 | MoonBit 版 | 说明 |
|:---|:---|:---|:---|
| funasr-gguf（默认，fun-asr-nano） | ✅ | ✅ | 经 `llama-funasr-cli` 子进程推理，MoonBit 编排 |
| funasr（torch） | ✅ | ❌ 裁剪 | torch 无法从 MoonBit 调用；裁剪后规避 GB 级 ML 栈依赖 |
| qwen-asr | ✅ | ❌ 裁剪 | 同上 |

裁剪后果：MoonBit 版 Service 的模型注册表仅登记 GGUF 类模型；Python 版三引擎能力保留在 Python 实现中不受影响。比赛语境下属合理取舍，文档中明确说明。

### 2.4 MoonBit 占比核算

三组件 MoonBit 重写后估计 6k~10k 行有效代码，本期 Python 侧零新增，占比天然 ≥ 80%。若评审对规模有更高要求，备选加码项：将 Client 侧识别请求编排 / 输出策略等纯逻辑抽为 MoonBit 库经 Socket 提供（本期不做，列为扩展项）。

## 3. 仓库布局

新增顶层目录 `moonbit/`（单一 MoonBit module，便于占比统计与统一构建）：

```text
# moonbit/（规划布局）
moonbit/
├── moon.mod.json            # 单 module
├── README.md                # 构建 / 运行 / 与 Python 组件对接说明
├── protocol/                # 对应 Zen_VocoType_Protocol：frames / actions / errors / paths / settings
├── service/                 # 对应 Zen_VocoType_Service：main / server / models / gguf 编排 / 单实例锁
└── launcher/                # 对应 Zen_VocoType_Launcher：main / 编排 / 就绪等待 / 实例识别 / 进程回收
```

- 现有四个 Python 组件目录**原样保留**，Python 版作为行为基线与测试参照继续可用
- 🔴 临时文件 / 构建缓存遵守 AGENTS.md 红线：MoonBit `target/` 目录本就落在 module 内，合规；测试数据落 `./.temp/`
- 路径契约沿用 `Zen_VocoType_Protocol/src/zen_vocotype_protocol/paths.py` 的 XDG 分层约定（Socket / 锁 / 日志 / 模型缓存位置不变），MoonBit 侧逐字实现同一套路径解析，🔴 否则 Python Client 与 MoonBit Service 找不到同一个 Socket
