## 3. 任务清单

> 负责人：AI 执行，用户审阅。预计总耗时：1.5~2 个工作日。
> 任务顺序按依赖关系排列，🔺 为检查点（Checkpoint）。

### T1.1 协议层实现（契约库 `frames.py` 落地）　【高】【预计 1.5h】

- **内容**：
  1. 实现 `encode_frame(header, body)` 与 `MessageBuffer.feed/next_frame`（复合帧：`[4 字节大端头长度][JSON 头 UTF-8][二进制体]`）
  2. 防御性上限落实：头超 `MAX_HEADER_BYTES`（64KB）、体超 `MAX_BODY_BYTES`（约 10 分钟录音）即判损坏，抛出契约库定义的明确异常（由服务端捕获后按协议 §7 断连）
  3. 单元测试（契约库 `tests/`）：编解码往返、空体帧、粘包（两帧一字节流）、拆包（一帧分多次 feed）、头/体超限拒绝、JSON 头非法
- **产出**：契约库 `frames.py` 实现 + pytest 全绿记录
- **依赖**：无（骨架已就位）
- **红线**：🔴 不复制旧 GridChat `socket_protocol.py`，仅沿用其经协议文档定稿的设计；`MessageBuffer` 实例必须每连接独立（协议 §7-3）

### T1.2 服务端基座：日志 + 配置扩展 + 单实例锁　【高】【预计 2h】

- **内容**：
  1. `logging_setup` 模块：loguru 双 sink（控制台 + `logs/` 轮转文件，10MB × 5 份，命名常量），格式含时间/级别/模块/**线程名**；全局替换入口，🔴 全组件禁 print
  2. `config.py` 扩展：`models: dict[str, ModelEntry]` 注册表字段（ModelEntry：`model_id` / `local_path` 二选一、`vad_model_id`、`punc_model_id`），缺省内置 paraformer-large 与 sensevoice-small 两条；启动校验 `default_model ∈ 注册表`，🔴 不存在即报错退出非零；推理超时（默认 60s）、队列阈值（默认 4）、连接上限（默认 8）作为命名常量入 `Settings` 并注明依据；`pyproject.toml` 补登 loguru
  3. 契约库 `paths.py` 增补 `SERVICE_LOCK_PATH` 常量（锁文件路径唯一出处，选型七；Launcher 阶段 3 读 PID 停服依赖此项）：🔴 必须落在 `DEFAULT_RUNTIME_DIR` 用户私有运行目录（与 Socket 路径同约定，禁止 /tmp 可预测路径）
  4. 单实例模块：`fcntl.flock(LOCK_EX | LOCK_NB)` 抢锁，失败报「已有实例运行」非零退出；持锁后写入自身 PID
  5. 单元测试：锁竞争（双进程抢锁其一失败）、kill -9 后无 stale 锁可直接重启、注册表校验（缺 default_model / 非法条目）
- **产出**：`logging_setup.py`、`config.py` 扩展、契约库 `paths.py` 增补、锁模块 + 测试记录
- **依赖**：无（可与 T1.1 并行）
- **红线**：loguru 封装为服务端自有模块，🔴 禁止跨组件 import；锁文件路径只准引用契约库常量，禁止另写

### T1.3 Socket 服务与连接管理　【高】【预计 2.5h】

- **内容**：
  1. 主线程 accept 循环 + 每连接守护线程收发循环（选型一）；连接上限 8（T1.2 配置项），超限拒绝并记日志
  2. 每连接独立 `MessageBuffer`；解析失败返回 `1001`/`1004`，超上限帧按协议 §7 断连；未知 action 返回 `1002`；**已定义未实现的 `audio_chunk` 入站校验放行后由分发层返回 `1005`**（协议 §3.6 机制，契约库 `ALL_ACTIONS` 注释已写明）
  3. **Socket 本地访问控制（协议 §7.1 v1 强制项，🔴 缺失即实现缺陷）**：bind 前校验目标路径非符号链接且属主为自身 → bind 后显式 `chmod 0600`（不依赖 umask）→ accept 时 `SO_PEERCRED` 校验对端 UID、非本 UID 拒绝并返回 `1006`
  4. action 路由表 → 处理器注册；`health`/`ready` 处理器先行实现（不依赖模型）：`health` 返回协议版本 + 服务状态，`ready` 按就绪语义返回（协议 §6）
  5. 线程安全服务状态对象：`starting → ready / error`（选型一；加载失败时 `health.status=error` 且 `ready` 返回 `3002` 真实原因）
  6. SIGTERM 确定性退出序列：停止 accept → 拒绝新请求 → 通知推理队列停止 → 释放模型 → 删除 Socket 文件 → 释放锁；全程日志
  7. 集成测试：本机起服务，socket 直发帧验证 health/ready/错误帧/版本握手（`1003`）；**§7.1 强制项实测：Socket 文件权限确为 0600、`audio_chunk` 返回 1005**（SO_PEERCRED 异 UID 拒绝以单元测试覆盖）
- **产出**：`server.py`、`connection.py`、`state.py` 等模块 + 集成测试记录
- **依赖**：T1.1、T1.2
- **红线**：🔴 先监听后加载——accept 循环启动不得等待任何模型操作；任何 handler 异常必须转化为协议错误响应，禁止连接悬挂（协议 §7-2）

### T1.4 模型注册表加载管线与异步启动　【高】【预计 3h】

- **内容**：
  1. `main.py` 第一行（任何 funasr/modelscope import 之前）设置 `MODELSCOPE_CACHE = Settings.models_dir`，**单元测试固化该顺序**（选型文档 §11-2）
  2. 缓存命中验证：以现有 `models/models/iic--*` 布局实测 `AutoModel(model=...)` 离线命中；🔴 命中失败按 R1 处置，禁止静默在线重下冒充命中
  3. 模型加载器：按注册表条目分发构造 `AutoModel`（`model_id` 缓存加载 / `local_path` 直接加载；VAD、标点附属模型按条目挂载；显式 `disable_update=True` 防在线检查拖慢启动）；加载失败抛带真实原因的异常，🔴 无任何假模型兜底
  4. 试推理自检：加载完成后以内置极短测试音频（新增 `assets/selftest_16k.pcm`，真实语音片段，🔴 禁止空输入假装自检）跑一次推理，仅验证「推理通路可用 + 返回结构合法」，不验证识别质量
  5. 异步加载线程接入：服务启动即监听（T1.3），后台线程执行 加载→自检→推进状态 `ready`/`error`
  6. 单元/集成测试：注册表驱动加载（paraformer-large 与 sensevoice-small 各加载一次并自检）、加载失败状态正确暴露
- **产出**：`models/registry.py`、`models/loader.py`、自检音频资产 + 测试记录（含缓存命中结论）
- **依赖**：T1.2；与 T1.3 可并行开发，集成点在 T1.5/T1.6
- **红线**：加载路径全部基于 `Settings.models_dir`（程序自身目录解析），🔴 禁 cwd 相对路径、禁家目录依赖

### T1.5 推理队列与 recognize / model_info / model_switch　【高】【预计 3h】

- **内容**：
  1. 单 worker 推理队列（选型四）：请求入队带超时预算（默认 60s，T1.2 配置项；T1.6 实测标定后可调）；队列积压超阈值（默认 4）直接拒绝
  2. `recognize`：JSON 头格式校验 + 体字节数一致性校验（不符 → `4001`）→ 未就绪 → `2001` → 入队推理 → 返回文本/置信度/时长；推理异常 → `4002` 带真实原因
  3. `model_info`：当前模型 + 注册表全量列表（含各模型加载来源）
  4. `model_switch` 原子切换（选型三）：操作入队（与推理天然互斥）→ 目标不在注册表 → `3001` → 加载新模型失败 → `3002` 且旧模型不受影响 → 试推理自检失败 → `3003` 回滚 → 替换引用 → 释放旧模型 → `model_info` 可交叉验证
  5. **错误码映射定稿**（⚠️ 红线）：推理超时 → `4002`（message 注明 `timeout`）；队列满 → `2002`；切换中收到 `recognize` → `2002`（message 注明 `model_switching`）。🔴 禁止擅自新增错误码；如确需新码，必须同步修订契约库 `errors.py` + 协议文档 §4 后方可使用
  6. 单元/集成测试：切换后 `model_info` 交叉验证、切换失败回滚、未就绪拒绝、音频非法拒绝、队列满拒绝
- **产出**：`inference/worker.py`、`handlers/` 三处理器 + 测试记录
- **依赖**：T1.3、T1.4

### T1.6 集成端到端测试与冷启动实测　【高】【预计 2h】

- **内容**：
  1. 端到端脚本（`tests/` 集成测试，模拟客户端发复合帧）：启动 → `health`(starting) → 轮询 `ready` → `recognize`（真实测试音频，断言返回非空文本）→ `model_switch` → `model_info` 交叉验证 → `model_switch` 切回 → SIGTERM 优雅退出
  2. **冷启动实测**（验收标准 1）：从进程启动到 Socket 可连接计时，连测 ≥5 次记录分布，须 ≤ 5 秒；同时记录到 `ready` 的模型加载耗时——🔺 **该数据是阶段 3 Launcher 超时预算的 P99 输入，必须落盘**
  3. 推理超时预算标定：以最长预期录音（60s 配置上限对应的 PCM）实测 CPU 推理耗时，校验 60s 超时预算合理性，偏差则调整默认值并注明依据
  4. 静态检查：全组件无 `print`、无 cwd 相对路径、无跨组件 import（rg 检查记录）
- **产出**：端到端测试脚本 + 冷启动/推理耗时实测数据（落入验收记录）
