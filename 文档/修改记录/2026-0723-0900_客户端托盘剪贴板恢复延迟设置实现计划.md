# 客户端托盘「剪贴板恢复延迟」设置项实现计划（T35）

## 1. 背景与现状

`paste_restore_delay_ms`（粘贴后恢复原剪贴板内容的延迟，默认 200ms）当前为
**纯静态配置**：`config.py` 的 `Settings.paste_restore_delay_ms` 在启动时读取
一次，装配进 `OutputPipeline(restore_delay_ms=...)`（`app.py:164`）后不再可变。
用户想调延迟只能手工编辑 `config.yaml`，且打包形态（AppImage 只读挂载点）下
包内 `config.yaml` 根本不可写。

2026-07-23 默认值刚从 500ms 调整为 200ms——这是一个**存在真实取舍**的参数：
个别读取剪贴板偏慢的应用在 200ms 窗口下可能粘贴出旧内容，需要用户可按本机
实际情况快速调大。手改 YAML 的门槛与这个诉求不匹配。

用户诉求：托盘右键菜单新增一个设置入口，图形化修改该延迟，**即时生效 +
长久化保存**（重启后仍然生效）。

### 关键存量资产（调研结论，本计划大量复用）

| 资产 | 位置 | 本计划用途 |
|---|---|---|
| 用户配置文件层 | 契约库 `zen_vocotype_protocol.user_config` | **持久化的唯一合法落点**：`set_user_config_value("paste_restore_delay_ms", ms)` 原子写入 `$XDG_CONFIG_HOME/zen_vocotype/user_config.yaml`；🔴 禁止写包内 `config.yaml`（AppImage 只读挂载点） |

| 字段校验 | `config.py:Settings.paste_restore_delay_ms`（`Field(ge=0)`） | 合法性约束的单一出处；UI 下限与之对齐 |

| 环境变量警示先例 | T33 的 `HOTKEY_ENV_VAR` 检测与通知文案 | 同法处理 `ZEN_VOCOTYPE_CLIENT_PASTE_RESTORE_DELAY_MS` |

## 2. 目标与非目标

### 2.1 目标

1. 托盘右键菜单新增「剪贴板恢复延迟…」项（菜单文本实时展示当前值，如
   `剪贴板恢复延迟（200ms）…`），点击弹出数值输入对话框。
2. 新延迟**即时生效**（不重启客户端）：`OutputPipeline` 运行态更新，
   下一次识别输出即按新延迟调度恢复。
3. 新延迟**持久化**：经契约库 `set_user_config_value` 写入用户配置文件，
   重启后自动生效（配置源链现成）。
4. 非法输入（负数、非整数）在对话框/应用层双重拦截，🔴 禁止落盘非法值
   导致下次启动 `validate_startup` 崩溃。

### 2.2 非目标

- 不改协议库、不改服务端/启动器任何代码
- 不做通用「设置中心」对话框（本计划只覆盖这一个参数；后续参数增多时再议）
- 不做延迟生效于「已在调度中的恢复任务」（进行中的恢复按排程时的旧延迟
  完成，属可接受语义，见 §5）
- 不改 `validate_startup` 启动校验逻辑（新值入库前已校验，启动期校验保持
  不变作为兜底）

## 3. 方案设计

### 3.1 总体流程

```
托盘「剪贴板恢复延迟（XXXms）…」
      │  restore_delay_change_requested 信号
      ▼
app.py:_on_change_restore_delay()（主线程）
      │  QInputDialog.getInt（预填当前值，min=0，max=10000，step=50）
      │  用户取消 → 直接返回
      ▼  取得 value
app.py:_apply_restore_delay(value)
  ① value >= 0 兜底校验（对齐字段 ge=0 约束）
  ② set_user_config_value("paste_restore_delay_ms", value)   ← 持久化（先落盘）
  ③ self._pipeline.set_restore_delay_ms(value)               ← 运行态切换
  ④ self._settings.paste_restore_delay_ms = value            ← 内存同步
  ⑤ tray.set_restore_delay_label(value) + 通知「恢复延迟已更新为 Xms」
  任一步失败 → 不变更任何运行态（先落盘顺序保证），通知用户
```

**顺序决策：先落盘后切换**（沿用 T33/T34）。落盘失败（如 XDG 目录不可写）
时整体放弃，运行态延迟不变——避免「运行态已换、重启后丢失」的知行分裂。

**无需忙碌守卫**：与热键不同，本参数不与状态机/事件流交互，仅影响
`OutputPipeline` 下一次 `output()` 的调度参数。录音/识别进行中修改完全
安全，故🔴 不复制 T33 的 IDLE 守卫（避免无依据的交互限制）。

### 3.2 详细改动点

#### (1) `output/restore.py`：运行态更新入口

`OutputPipeline` 新增：

```python
def set_restore_delay_ms(self, ms: int) -> None:
    """运行态更新恢复延迟（托盘设置项热切换用）；仅影响后续 output() 调度。"""
    if ms < 0:
        raise ValueError(f"恢复延迟非法：{ms}")
    self._restore_delay_ms = ms
```

- 防御性校验与 `Settings` 字段 `ge=0` 对齐（调用方已校验，此为底层红线）；
- 纯赋值，无线程安全问题：调度读取发生在主线程 `output()` 内。

#### (2) `tray/tray.py`：菜单扩展

在「修改快捷键…」项之后追加（同属设置区，不分新组）：

```
│ 修改快捷键…                          │ （不变）
│ 剪贴板恢复延迟（200ms）…             │ 新增：当前值直接编入文本，随切换刷新
├─────────────────────────────────────┤
│ 保存录音                            │ （不变，T34 功能组）
```

- `ClientTray` 新增信号 `restore_delay_change_requested = Signal()`；
- 新增 `set_restore_delay_label(ms: int)`：
  `self._restore_delay_action.setText(f"剪贴板恢复延迟（{ms}ms）…")`；
  当前值编入菜单文本（而非独立禁用展示行）——延迟是低关注参数，
  不为它增加一行常驻视觉噪音（快捷键是高频参照物，待遇不同）；
- 构造时初始文本用占位 `剪贴板恢复延迟（—）…`，由装配层注入实值；
- ⚠️ 沿用 PySide6 GC 陷阱教训：action 引用持久持有
  `self._restore_delay_action`，测试不经 `contextMenu().actions()` 查找。

#### (3) `app.py`：热切换编排

```python
def _on_change_restore_delay(self) -> None:
    """托盘「剪贴板恢复延迟…」入口（主线程）。"""
    value, ok = QInputDialog.getInt(

        "粘贴后恢复原剪贴板内容的延迟（毫秒）：\n"
        "个别应用粘贴出旧内容时可调大（如 300~500）",
        self._settings.paste_restore_delay_ms, 0, 10000, 50,
    )
    if ok:
        self._apply_restore_delay(value)

def _apply_restore_delay(self, value: int) -> None:
    """校验 → 落盘 → 切换 → 内存/界面同步；失败不生效并通知。"""
```

`_apply_restore_delay` 步骤与失败处理：

| 步骤 | 失败处理 |
|---|---|
| ① `value < 0` 兜底校验 | 通知「延迟数值非法」；不变更任何状态 |
| ② `set_user_config_value("paste_restore_delay_ms", value)` | 通知「配置写入失败：…」；运行态保持不变（🔴 禁止先切后写） |
| ③ `self._pipeline.set_restore_delay_ms(value)` | 不会失败（①已校验，③校验为底层红线双保险） |
| ④ `self._settings.paste_restore_delay_ms = value`、`tray.set_restore_delay_label(value)`、成功通知 | 不会失败 |

- 环境变量警示：新增常量
  `config.RESTORE_DELAY_ENV_VAR = "ZEN_VOCOTYPE_CLIENT_PASTE_RESTORE_DELAY_MS"`
  （🔴 与 `HOTKEY_ENV_VAR` 同模式，禁止散落硬编码）。`_apply_restore_delay`
  检测到该环境变量存在时，成功通知追加「检测到环境变量
  ZEN_VOCOTYPE_CLIENT_PASTE_RESTORE_DELAY_MS，重启后将以其为准」——
  不阻断操作，仅如实告知；
- 接线：`tray.restore_delay_change_requested.connect(self._on_change_restore_delay)`；
  托盘构造后调一次 `tray.set_restore_delay_label(settings.paste_restore_delay_ms)`
  初始化文本。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 写包内 config.yaml（AppImage 只读必失败） | 持久化唯一走契约库 `set_user_config_value`（用户配置文件层），包内文件只读不动 |
| 环境变量优先级高于用户配置文件导致「改了不生效」困惑 | `_apply_restore_delay` 检测 `ZEN_VOCOTYPE_CLIENT_PASTE_RESTORE_DELAY_MS` 并通知提醒；README 说明优先级链 |
| 负数/非法值落盘导致下次启动 validate_startup 崩溃 | 双层拦截：`QInputDialog.getInt(min=0)` UI 层 + `_apply_restore_delay` 兜底校验 + `OutputPipeline.set_restore_delay_ms` 底层红线；非法值永不触达落盘 |
| 进行中的恢复任务受新值影响产生语义混乱 | 已排程的 `QTimer.singleShot` 不可变且按旧值完成——这正是期望语义（该任务粘贴时的应用读取窗口按旧值评估）；新值只影响后续输出，文档如实说明 |
| 用户设 0ms 导致目标应用读不到识别文本 | 字段约束 `ge=0` 允许 0（立即恢复），属用户自主调参权；README 调参指引说明「粘贴出旧内容 → 调大」，对话框说明文案同步提示 |
| PySide6 action 临时包装 GC 陷阱（服务端托盘已踩） | action 引用持久持有 `self._restore_delay_action`；测试不经 `actions()` 临时包装查找 |
| 用户配置文件中该项被手改为非法值 | 既有 `validate_startup` 启动校验兜底，启动即明确报错（现状不变） |

## 6. 待审阅确认点

1. **菜单项形态**：当前值编入可点击项文本 `剪贴板恢复延迟（200ms）…`
   （本计划方案）vs 仿快捷键拆「禁用展示行 + 修改项」两行——本计划取前者
   （低关注参数不占常驻行）。
2. **输入控件**：`QInputDialog.getInt`（原生、零自绘、min/max/step 内置，
   本计划方案）vs 自绘对话框带「恢复默认（200ms）」按钮——本计划取前者；
   「恢复默认」可通过直接输入 200 达成，README 注明默认值。
3. **上限**：UI 上限 10000ms（10 秒，防误输天文数字）是否合适；字段本身
   无 `le` 约束，超出 UI 上限的值仍可通过手改 YAML 设置（不影响）。
4. **步进**：getInt step=50ms 是否合适（备选 100）。
5. **无忙碌守卫**：录音/识别中允许修改（本计划方案）vs 统一仿 T33 仅
   IDLE 放行——本计划取前者（该参数与状态机零交互，守卫无依据）。
