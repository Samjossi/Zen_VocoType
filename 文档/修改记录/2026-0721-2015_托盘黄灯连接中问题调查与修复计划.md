# 托盘黄灯「连接中…」误报问题调查与修复计划（方案 A：LOADING 态轮询）

## 1. 现象

客户端已成功连接服务端（识别功能完全正常，日志可见 `识别完成：N 字符`），
但托盘图标始终停留在**橙色（黄）「连接中…」**，识别结束归位后仍不转绿。

## 2. 调查证据（2026-07-21 20:07–20:09 实跑日志）

**服务端 `Zen_VocoType_Service/logs/service.log`：**

```
20:07:27.762  开始加载模型 paraformer-large
20:07:34.105  连接建立: conn-1            ← 客户端此刻 probe（服务端仍 starting）
20:07:34.938  服务就绪（ready），当前模型: paraformer-large
```

**客户端 `Zen_VocoType_Client/logs/client.log`：**

```
20:08:49.464  识别完成：0 字符            ← 功能正常，服务端早已 ready
20:08:49.468  托盘状态更新：CONNECTING     ← 归位 idle 后仍刷回「连接中…」
```

## 3. 根因分析

1. **probe 仅执行一次**（主因）：`ClientApp.start()`（app.py:143）只在启动时调用一次
   `worker.probe()`。启动 probe 时服务端模型尚在加载，health 返回 `status: "starting"`，
   `NetworkWorker._emit_status_from_health()`（worker.py:129-130）映射为
   `STATUS_LOADING` → 托盘 `TrayStatus.CONNECTING`。
2. **无就绪感知通道**：协议是请求-响应模型，服务端 `mark_ready` 后没有推送；
   客户端也没有任何周期轮询，状态永远停留在 `LOADING`。
3. **识别复用长连接时跳过 health 刷新**（放大主因）：`_ensure_connected()`
   （worker.py:100-103）连接已存在时直接 `return True`，不再发 health。
4. **状态缓存过期 + IDLE 归位回刷**（直接观感来源）：`_service_tray_status` 缓存了
   过期的 `CONNECTING`，识别完成归位 `IDLE` 时（app.py:209-210）回刷到托盘。

**结论**：不是连接/协议/服务端问题，是客户端「只在启动时探测一次 + 无轮询 +
状态缓存过期」导致的状态展示缺陷。修复只动客户端状态展示层，**不改协议与服务端**。

## 4. 修复方案（方案 A：LOADING 态周期轮询 health）

### 4.1 总体设计

客户端收到 `STATUS_LOADING`（服务端在线但模型未就绪）时，在主线程启动一个
`QTimer` 周期触发 health 探测，直到拿到终态（READY / ERROR / DISCONNECTED）
或达到轮询上限。全部网络 I/O 仍在网络 worker 线程执行，主线程只负责调度。

事件流：

```
worker.sig_service_status(LOADING) ──► app._on_service_status ──► 启动 _loading_poll_timer
QTimer.timeout ──► _request_probe() ──► QueuedConnection 投递 worker.probe()（worker 线程执行 health）
worker.probe() ──► sig_service_status(READY/ERROR/DISCONNECTED) ──► 停止 _loading_poll_timer
轮询次数达上限 ──► 停止定时器 + 托盘 CONNECTING(detail=加载超时) + 一次性通知引导手动重试
```

### 4.2 详细改动点

#### (1) `config.py`：新增两个配置项（命名常量 + 可配置，C2）

```python
#: 服务端模型加载中的 health 轮询间隔（毫秒）。
#: 依据：本地 Socket 往返毫秒级，3s 间隔对服务端无压力且用户可感知的等待可接受
loading_poll_interval_ms: int = Field(default=3000, ge=500)

#: LOADING 态轮询最大次数（默认 120 次 × 3s ≈ 6 分钟，覆盖大模型冷启动加载）。
#: 达上限停止轮询并提示手动重试——落实「禁止后台无限重试」红线（选型二）
loading_poll_max_count: int = Field(default=120, ge=1)
```

#### (2) `worker.py`：`probe()` 轻化（避免每次轮询重建长连接）

现状 `probe()` 无条件 `self._client.connect()`，而 `connect()` 会先 `close()` 旧连接——
轮询期间若识别长连接健康存在，会被反复无谓重建。改为：

```python
@Slot()
def probe(self) -> None:
    """health 探测；连接健康时直接复用长连接发 health，不重建。"""
    try:
        if not self._client.connected:
            self._client.connect()
        payload = self._client.health()
    except VersionMismatchError as exc:
        ...  # 保持现状
    except (ServiceUnavailableError, RequestFailedError) as exc:
        ...  # 保持现状（close + DISCONNECTED）
    self._emit_status_from_health(payload)
```

行为变化仅限「已连接时少一次 TCP 级重建」，对外信号语义不变，既有测试不回归。

#### (3) `app.py`：轮询定时器接线（核心）

```python
#: 类常量提示文案（T2.7 文案风格，单一出处）
MSG_LOADING_TIMEOUT = "服务端模型加载等待超时——请从托盘菜单「重试连接服务端」"

# __init__ 中新增：
self._loading_poll_timer = QTimer(self)
self._loading_poll_timer.setInterval(settings.loading_poll_interval_ms)
self._loading_poll_timer.timeout.connect(self._on_loading_poll_tick)
self._loading_poll_count = 0

# 抽取探针投递为公共助手（start()/_on_retry/轮询三处共用，消除三份重复）：
def _request_probe(self) -> None:
    if self._qthread is not None:
        QMetaObject.invokeMethod(self._worker, "probe", Qt.ConnectionType.QueuedConnection)

# _on_service_status 中启停定时器（在现有 mapping 之后追加）：
if status == worker_mod.STATUS_LOADING:
    self._loading_poll_count = 0
    if not self._loading_poll_timer.isActive():
        self._loading_poll_timer.start()
else:
    self._loading_poll_timer.stop()
    self._loading_poll_count = 0

# 轮询 tick：
def _on_loading_poll_tick(self) -> None:
    self._loading_poll_count += 1
    if self._loading_poll_count > self._settings.loading_poll_max_count:
        self._loading_poll_timer.stop()
        self._loading_poll_count = 0
        self._set_tray(TrayStatus.CONNECTING, "模型加载超时")
        self._notifier.notify(APP_DISPLAY_NAME, MSG_LOADING_TIMEOUT, key="loading-timeout")
        return
    self._request_probe()
```

同时 `start()` 与 `_on_retry()` 改为调用 `_request_probe()`（语义不变）。

#### (4) `app.py::shutdown()`：确定性退出补一刀

`shutdown()` 开头 `self._loading_poll_timer.stop()`，防止退出序列中定时器触发
向已停 worker 线程投递探针。

### 4.3 关键边界与决策

| 场景 | 行为 | 依据 |
|------|------|------|
| 轮询中用户点「重试连接」 | `_request_probe()` 直接投递一次 probe，计数器不重置（`_on_service_status` 收到新状态自然重置） | 手动操作优先，语义简单 |
| 轮询中用户发起识别 | `recognize` 槽与 `probe` 槽同在 worker 线程事件队列串行执行，无并发 Socket 访问 | QThread 单线程事件循环天然互斥 |
| LOADING → ERROR | 停止定时器，托盘红态（现有映射） | 终态收敛 |
| LOADING → DISCONNECTED（服务端崩溃） | 停止定时器，托盘灰态 + 现有「服务端未运行」通知 | 🔴 断连态不自动轮询，手动重试（选型二红线） |
| 达到 `loading_poll_max_count` | 停止 + 托盘 detail「模型加载超时」+ 一次性通知（走 notifier 去重） | 禁止无限轮询红线 |
| `notify_dedup_seconds` 内重复超时 | 由现有 Notifier 去重抑制 | 禁止通知轰炸红线（选型九） |

### 4.4 不改动的部分（明确排除）

- ❌ 不改协议、不改服务端任何文件；
- ❌ 不改 `recognize` 路径与错误码透传语义；
- ❌ 不引入「识别成功即推断 ready」的隐式状态纠正（保持状态来源唯一：仅 health 驱动）；
- ❌ DISCONNECTED 态不增加任何自动重试。

## 6. 测试设计

| 用例 | 方法 | 断言 |
|------|------|------|
| LOADING 启动轮询 | 构造 `ClientApp`（stub server 返回 `status:"starting"`），`qapp` + `QSignalSpy` | 收到 LOADING 后 `timer.isActive()` 为真 |
| READY 停止轮询 | stub 先 starting 后切 ready，推进事件循环 | 收到 READY 后定时器停止、托盘状态 READY |
| DISCONNECTED 不轮询 | stub 停服后触发 probe | 定时器停止，不再投递 probe（worker probe 调用次数冻结） |
| 上限停止 | `loading_poll_max_count=2` 注入 | 第 3 次 tick 后定时器停止、发出 `loading-timeout` 通知、托盘 detail 含「模型加载超时」 |
| probe 复用长连接 | stub server 计数 accept 次数 | 连续两次 `probe()` 只产生一次新连接 |
| shutdown 幂等 | 轮询激活中调用 `shutdown()` | 定时器停止，无悬挂投递、进程正常退出 |

## 7. 约束与红线（不得破坏）

- 🔴 网络 I/O 只在网络 worker 线程：轮询经
  `QMetaObject.invokeMethod(..., QueuedConnection)` 投递，禁止主线程直接调 `probe()`。
- 🔴 「禁止后台无限重试」红线（选型二）：轮询仅限已知在线的 LOADING 态且有次数上限；
  DISCONNECTED 态仍只允许手动重试。
- 🔴 错误码透传语义不改写；托盘状态来源唯一（health 驱动），不做隐式推断。
- 🔴 配置项命名常量 + 可配置（C2），禁止魔法数字散落。

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 轮询与识别请求在 worker 队列排队导致识别延迟 | health 为毫秒级轻请求，3s 间隔影响可忽略；实测验证步骤 3 覆盖 |
| 大模型冷启动超过默认 6 分钟上限 | 上限可配置；超时后有明确通知与手动重试路径 |
| QTimer 在退出序列中触发悬挂投递 | shutdown() 显式 stop；任务 4 单测覆盖 |
