# 统一版本管理（TOML）实现计划

## 1. 背景与现状

四个组件各自维护版本号，**位置分散、格式不统一**：

| 组件 | 当前版本 | 格式 | 出处位置 | pyproject 读取方式 |
|---|---|---|---|---|
| Client | `0.2.0` | 三位 | `src/zen_vocotype_client/__init__.py` 的 `__version__` | `dynamic`（hatch 读 `__init__.py`） |
| Launcher | `0.1.0` | 三位 | **仅** `pyproject.toml` 静态字段 | 静态 `version = "0.1.0"`，代码中无任何版本引用 |
| Protocol | `1.0.0` | 三位 | `src/zen_vocotype_protocol/version.py` 的 `PROTOCOL_VERSION` | 静态 `version = "0.1.0"`（⚠️ 与代码值 `1.0.0` **不一致**，已存在漂移） |
| Service | `1.0` | 两位 | `src/zen_vocotype_service/version.py` 的 `SERVICE_VERSION` | `dynamic`（hatch pattern 读 `version.py`） |

版本号的下游使用点：

- **Protocol**：`PROTOCOL_VERSION` 经 health 握手交换，`parse_version()` 强制三段式、
  `is_compatible()` 按 `major.minor` 严格比对（client `transcribe/client.py` 与
  service `connection.py` / `server.py` / `protocol_io.py` 共用）。
- **Client**：`__version__` 用于托盘菜单首行版本项显示。
- **Service**：`SERVICE_VERSION` 用于 health 响应 `service_version` 字段与托盘版本项。
- **Launcher**：无任何代码引用，纯打包元数据。

## 2. 问题

1. **格式不统一**：两位（Service `1.0`）与三位（其余三家）混用，比较与展示语义有歧义。
2. **出处分散**：改版本要分别编辑 4 处文件，已实际发生漂移（Protocol 代码 `1.0.0`
   vs pyproject `0.1.0`）。
3. **无单一真相**：无法回答「整个项目现在是什么版本」。

## 3. 目标与非目标

### 3.1 目标

1. 仓库根目录新增 **`versions.toml`** 作为四组件版本号的**唯一真相**（Single Source
   of Truth），版本更新只改这一个文件。
2. 版本号格式统一为**两位数 `major.minor`**（如 `1.0`），未来延续 `1.1`、`1.2`、
   `2.0`…，不再使用三段式（延续 Service 已定版的产品决策）。
3. 提供**同步机制**将 `versions.toml` 的值写入各组件本地出处（版本不同步时
   一致性测试变红，禁止静默漂移）。
4. Protocol 的 `parse_version()` / `is_compatible()` 适配两段式，握手字段值随
   `PROTOCOL_VERSION` 一并切换（两端共用同一 protocol 包，天然同步）。

### 3.2 非目标

- 不改版本号的下游消费逻辑（握手比对策略、托盘显示、health 字段名均不变，
  仅版本字符串本身变短）
- 不引入 CHANGELOG.md（如需变更记录，后续单独立项）
- 不调整各组件的构建后端（hatchling 维持现状）
- 不做打包（PyInstaller/AppImage）场景验证，但方案设计须保证打包后版本可用
  （见 §4.2 架构决策）

## 4. 方案设计

### 4.1 `versions.toml` 文件格式

位置：仓库根目录 `Zen_VocoType/versions.toml`（与四组件目录平级）。

```toml
# Zen_VocoType 统一版本管理 —— 版本号唯一真相
#
# 规范：
#   1. 版本号为两位数格式 major.minor（如 "1.0"），未来延续 1.1、1.2、2.0…
#   2. 版本更新只改本文件，随后运行 tools/sync_versions.py 同步至各组件
#   3. 各组件一致性测试会比对本地出处与本文件，不同步即测试失败

[meta]
spec = "major.minor"

[components]
client   = "0.2"
launcher = "0.1"
protocol = "1.0"
service  = "1.0"
```

**基线映射（🔴 待审阅裁决，见 §7-1）**：按现状截断迁移——Client `0.2.0→0.2`、
Launcher `0.1.0→0.1`、Protocol `1.0.0→1.0`、Service `1.0→1.0`（不变）。
不借机统一拉齐到同一版本号：各组件独立演进，版本号各自递增。

### 4.2 读取架构（核心决策）

**推荐方案：唯一真相 + 构建期同步 + 一致性测试**（而非运行时跨目录读取）。

```
versions.toml（唯一真相，人工维护）
     │
     │ tools/sync_versions.py（开发期手动运行）
     ▼
各组件本地出处（version.py / __init__.py / pyproject.toml）
     │
     │ 运行时/打包时（维持现状，无任何跨目录依赖）
     ▼
托盘显示 / health 响应 / 握手 / wheel 元数据

各组件一致性测试：读 ../../versions.toml 比对本地出处，漂移即失败
```

**为什么不采用「运行时直接读 `../../versions.toml`」：**

- 组件以 wheel 安装或被 PyInstaller 打包后，**不存在仓库根目录的兄弟文件**，
  运行时读取必然引入「开发环境/安装环境」双路径分支与降级逻辑，正是客户端
  icon_loader 文档点名的相对路径反模式；
- 本地出处 + 同步脚本后，运行时代码**一行不用改**（仍读本地 `version.py`），
  打包安全；
- 漂移防护由一致性测试承担，红线从「运行时兜底」前移到「CI/本地测试拦截」，
  符合项目「禁止静默降级」的原则。

### 4.3 各组件改动点

#### (1) Protocol（改动最大）

- `version.py`：`PROTOCOL_VERSION` 改为 `"1.0"`；
- `parse_version()`：改为解析两段式，返回 `tuple[int, int]`，非法格式照旧抛
  `ValueError`（禁止静默降级红线不变）；
- `is_compatible()`：两段式下退化为**完全相等**比较（major.minor 即全部），
  语义与现状「major.minor 一致才兼容」**完全一致**，无行为变化；
- `pyproject.toml`：静态 `version` 由 `0.1.0` 改为与代码一致的动态读取
  （参照 Service 的 hatch pattern 方式），消除既有漂移：
  ```toml
  [project]
  dynamic = ["version"]

  [tool.hatch.version]
  path = "src/zen_vocotype_protocol/version.py"
  pattern = "PROTOCOL_VERSION: str = \"(?P<version>[^\"]+)\""
  ```
- 握手字段名 `protocol_version` 不变，值由 `"1.0.0"` 变 `"1.0"`；Client/Service
  均经 protocol 包取该值，两端天然同步，无跨版本握手窗口问题（同源升级）。

#### (2) Client

- `__init__.py`：`__version__ = "0.2.0"` → `"0.2"`；
- pyproject 的 hatch `path` 读取方式不变，无需改动；
- 🔴 **托盘右键菜单首行版本项**（`tray/tray.py` 的 `f"{APP_DISPLAY_NAME} v{__version__}"`）
  是本组件版本号的运行时消费点：它引用的就是 `__version__`，同步脚本改写本地
  出处后**托盘显示自动跟随，无需改托盘代码**；验收时必须实机确认（见 §5-6）。

#### (3) Service

- `version.py`：`SERVICE_VERSION` 已为 `"1.0"`，**值不变**，仅同步脚本将其纳入
  管理；hatch pattern 不变。
- 🔴 **托盘右键菜单首行版本项**（`tray/tray.py` 文本取 `version.py:SERVICE_VERSION`）
  与 health 响应 `service_version` 字段同为运行时消费点：二者引用同一本地出处，
  同步后自动跟随；本次值不变（`1.0`），但后续每次版本更新都须经 §5-6 实机确认
  托盘版本项已刷新。

#### (4) Launcher

- 新增 `src/zen_vocotype_launcher/version.py`：
  ```python
  """启动器软件版本号（单一出处，由 versions.toml 同步）。"""

  LAUNCHER_VERSION: str = "0.1"
  ```
- `pyproject.toml`：静态 `version = "0.1.0"` 改为 hatch pattern 动态读取
  （与 Protocol/Service 同模式），消除「只改 pyproject、代码无出处」的现状。

#### (5) 同步脚本 `tools/sync_versions.py`

- 位置：仓库根目录 `tools/`（新建目录）；
- 仅用标准库 `tomllib`（Python ≥3.11，项目要求 ≥3.12，零新依赖）；
- 逻辑：读 `versions.toml` → 逐组件按正则改写本地出处文件中的版本字符串 →
  打印每项改动；某组件文件缺失或正则未命中即**报错退出非零**（禁止静默跳过）；
- 执行入口统一走项目 `.venv`（AGENTS.md 红线），文档中写明：
  `Zen_VocoType_Protocol/.venv/bin/python tools/sync_versions.py`
  （或以各组件任一 .venv 解释器执行，脚本本身无第三方依赖）。

#### (6) 一致性测试

每个组件的 `tests/` 各新增一个 `test_version_consistency.py`（共 4 份，内容极短）：

```python
"""版本一致性：本地出处必须与仓库根 versions.toml 同步（防漂移红线）。"""
import tomllib
from pathlib import Path

VERSIONS_TOML = Path(__file__).resolve().parents[3] / "versions.toml"

def _root_version(component: str) -> str:
    with VERSIONS_TOML.open("rb") as f:
        return tomllib.load(f)["components"][component]
```

- Client：断言 `__version__ == _root_version("client")`；
- Service：断言 `SERVICE_VERSION == _root_version("service")`；
- Protocol：断言 `PROTOCOL_VERSION == _root_version("protocol")`，并补
  `parse_version("1.0") == (1, 0)`、三段式输入抛 `ValueError` 的用例；
- Launcher：断言 `LAUNCHER_VERSION == _root_version("launcher")`；
- 若仓库被单组件独立 clone（无 `../../versions.toml`），测试**显式 skip 而非
  通过/失败**（`pytest.skip`），避免阻塞组件独立开发。

#### (7) 文档更新

- 根 `versions.toml` 头部注释即维护规范（改版本 → 跑同步 → 跑测试）；
- 四组件 README 的版本相关表述统一指向 `versions.toml`；
- Service `version.py` 与 pyproject 注释中「🔴 两位数格式」的出处说明改为指向
  根 `versions.toml`（单一出处原则：规范说明也集中一处）。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 协议版本字符串从 `"1.0.0"` 变 `"1.0"`，若有旧版两端混部会握手失败 | 两端共用同一 protocol 包同源升级；失败路径本就是显式报错（1003 + 提示更新），符合预期 |
| 同步脚本忘记运行导致漂移 | 一致性测试拦截（测试即红线）；versions.toml 头部注释写明三步流程 |
| 组件独立 clone 后一致性测试找不到根文件 | 显式 `pytest.skip`，不误判 |
| Launcher 从无代码出处改为 version.py，遗漏引用点 | Launcher 目前**无任何**版本消费点，改动面收敛在 pyproject + 新文件 |
| sync 脚本正则误伤文件其他内容 | 每个组件只匹配带变量名的整行（如 `^SERVICE_VERSION: str = "..."$`），改写后二次 tomllib/AST 校验 |
