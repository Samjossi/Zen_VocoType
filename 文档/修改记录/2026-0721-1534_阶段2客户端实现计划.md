### T2.2 状态机模块　【高】【预计 1.5h】

- **内容**：

### T2.3 网络 worker：Socket 客户端与连接管理　【高】【预计 3h】

- **内容**：
  1. QThread 网络 worker（选型一）：Socket 长连接收发，`Signal` 回主线程；worker 对象 `moveToThread` 范式，退出时序干净
  2. 启动即 `health` 探测一次（选型二）：托盘即时展示服务端状态（就绪/加载中/未运行）；未连接 → 托盘灰态（🔴 禁止崩溃或静默失败，C1）
  3. 连接建立后立即执行协议版本握手（协议文档 §5）：版本不一致 → 断开 + 托盘红态 + 通知明确报错（🔴 禁止静默继续）
  4. 识别请求时懒连接长连复用；收到对端关闭或写失败 → 置「未连接」态并通知主线程更新托盘；**重连仅限一次立即尝试**（🔴 禁止后台无限重试刷日志；用户可经托盘菜单手动重试）
  5. 复合帧收发走契约库 `frames.py` API；收到协议错误码响应 → 转化为带错误码与 message 的失败事件回主线程（13 个冻结码原样透传，🔴 禁止改写语义）
  6. 模拟服务端桩（`tests/`）：基于契约库 frames 的内存/本机 Socket 桩，支持健康/版本不符/未就绪/识别成功/各错误码注入
  7. 单元/集成测试：health 探测三态、版本握手拒绝、长连复用、断线单次重连、识别往返、错误码透传

- **依赖**：契约库 `frames.py`（已随阶段 1 落地）

  2. 流实例复用（大纲交付物原文）：启停在同一流实例上进行，松开即停流拼接为单段 PCM，尾音完整

  4. 设备选择：默认系统默认输入设备，`input_device` 配置可覆盖；启动时探测并日志记录实际设备与采样率；**设备缺席启动即明确报错**（🔴 禁止录音时才发现）
