### T3.5 既有实例识别模块 `discovery.py`　【高】【预计 2h】

- **内容**：

  2. Socket 兜底探测：拉起 Service 前若业务 Socket 已存在且可连接 → `health` 探测；是本组件协议（版本握手通过）→ 复用并提示；非本组件协议/版本不符 → 报错「Socket 路径被外部占用」退出码 5（🔴 禁止 unlink 他人 Socket）
  3. dev 模式识别 dev 锁/dev Socket，正式模式识别正式锁/正式 Socket，互不干扰（C7）
  4. 单元测试：PID 存活+exe 匹配/不匹配/进程死三分支、Socket 占用两分支（本协议/外部占用）、陈旧锁清理
- **产出**：`discovery.py` + 测试记录

### T3.8 编排器 `orchestrator.py` + 退出码 `exit_codes.py`　【高】【预计 2.5h】　🔺

- **内容**：
  1. 退出码枚举（选型六）：`0` 成功（含幂等命中确认就绪）/`2` 已在运行或实例异常/`3` 服务端拉起或就绪失败/`4` 客户端拉起失败/`5` 配置或路径错误（含组件缺失、Socket 外部占用）/`6` 内部错误
  2. 编排主流程（选型七方案 A：拉起确认后即退出）：抢 Launcher 锁 → 识别既有实例（幂等分支）→ 拉起 Service → 两阶段就绪等待 → 拉起 Client → 确认 Client 进程存活 → 通知「启动完成（含总耗时）」→ **释放锁退出 0，不杀子进程**
  3. 失败清理（选型五方案 A）：`ExitStack` 逆序回收——Client 拉起失败回收 Service；就绪超时回收 Service；每步回收记日志；失败通知含失败阶段与日志位置提示
  4. 依赖注入装配（选型十）：Popen 工厂/等待器/通知器/时钟均可替换，fake 注入单测
  5. 单元测试（fake 驱动）：成功路径、幂等命中、Service 慢启动在预算内成功、Service 崩溃不误判且回收干净退出码 3、Client 拉起失败回收 Service 退出码 4、锁冲突退出码 2、Socket 外部占用退出码 5——**七场景全覆盖**（验收标准 2/3 的自动化核心）
- **产出**：`orchestrator.py`、`exit_codes.py` + 七场景测试记录
- **依赖**：T3.3~T3.7 全部
- **检查点 CP0**：七场景单测全绿记录提交用户确认
