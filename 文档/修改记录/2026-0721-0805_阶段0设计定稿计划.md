- **内容**：
  1. 按选型结论向 `.venv` 安装开发期基线依赖：`pydantic-settings`、`PySide6`、`pynput`、`sounddevice`、`pytest`（服务端重依赖 FunASR/torch 属阶段 1，本阶段不装）

  3. PySide6 冒烟验证：`.venv` 下可 `import PySide6`；在本机桌面环境实测 `QSystemTrayIcon.isSystemTrayAvailable()` 并记录结果（选型文档 D4 结论的环境佐证）
- **产出**：安装日志 + 托盘可用性冒烟记录（写入 T0.6 验收记录）
- **依赖**：无
- **红线**：只用项目 `.venv` 的 Python；安装失败不得静默跳过

### T0.2 协议契约库骨架搭建　【高】【预计 1.5h】

- **内容**：
  1. 清理 `Zen_VocoType_Protocol/` 残留的 `__pycache__`
  2. 创建 `pyproject.toml`（独立包，src 布局）
  3. 按选型 6/8 定稿模块划分并创建**骨架文件**（常量与空壳定义，🔴 不写业务实现）：
     - `version.py` — 协议版本号（版本握手用）
     - `frames.py` — 复合帧编解码骨架（`[4 字节头长度][JSON 头][二进制体]`）
     - `actions.py` — action 常量全集
     - `errors.py` — 错误码常量
     - `paths.py` — Socket 路径等全局关键项**唯一出处**的默认值
  4. `pip install -e ./Zen_VocoType_Protocol` 装入 `.venv`，冒烟验证 `import zen_vocotype_protocol` 及各子模块可导入
- **产出**：契约库骨架 + editable install 成功记录；模块划分说明并入 T0.3 协议设计文档
- **依赖**：T0.1
- **红线**：骨架即契约雏形，action/错误码常量必须与 T0.3 文档保持同源；禁止复制旧 GridChat 协议代码

### T0.3 通信协议设计文档撰写　【高】【预计 2h】　🔺

- **内容**：按选型 6/7/8 定稿并落盘：
  1. 复合帧格式：帧结构、长度前缀字节序、JSON 头字段表（action / 音频格式 / 音频字节数 / 协议版本）、粘包处理约定（MessageBuffer 思路沿用说明）
  2. action 全集：`health` / `ready` / `recognize` / `model_info` / `model_switch`，每个含方向、请求/响应字段、失败响应；为流式识别预留 `audio_chunk` 的帧复用说明（仅设计预留，不实现）
  3. 错误码表：错误码区间划分、各 action 可能的错误响应
  4. 版本握手：`health` 响应携带协议版本；两端版本不一致时客户端**明确报错**的语义（🔴 禁止静默继续）
  5. 就绪语义：`Socket 可连接` ≠ `模型已就绪`，`ready` 接口语义定义
- **产出**：`文档/通信协议设计_v1.0.md`（落盘位置如另有约定，审阅时指出）
