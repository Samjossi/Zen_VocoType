# 模型缺失与下载提醒 计划

## 1. 背景与问题

用户通过托盘「切换模型 ►」子菜单（或 Socket 客户端 `model_switch`）选择一个模型时：

- 若该模型权重**尚未缓存到本地**，服务不做任何提示，直接在后台经 ModelScope 静默下载；
- 下载期间（大模型可达数 GB、耗时数分钟到数十分钟）用户**完全无感知**——托盘状态只显示「切换中…」，无法区分「本地加载中」与「正在下载」；
- 用户甚至可能以为服务卡死而反复点击或重启。

**期望行为**：

1. 选择的模型本地不存在（未缓存）时，明确提醒用户「该模型尚未下载」；
2. 下载进行中，明确提醒用户「正在下载」，下载完成/失败也有对应反馈。

## 2. 现状分析（代码事实）

| 事实 | 出处 |
| --- | --- |
| 下载触发点集中在 loader：`model_id` 条目经 `snapshot_download` / `AutoModel` 隐式下载；`local_path` 条目本地下载不涉及 | `models/loader.py`（`_load_qwen3_asr`、`_load_funasr_gguf`、`load_model`） |
| 缓存探测逻辑已存在但**仅用于模型清单展示**，返回展示文案而非可复用判定 | `tray/models_dialog.py::cache_status`（按 `<models_dir>/models/<org>--<name>` 布局探测） |
| 托盘状态轮询快照为 `(status, model, detail, switching)`，仅 3 种持续状态（加载中/就绪/错误），无「下载中」概念 | `tray/tray.py::_refresh`、`state.py` |
| 托盘具备气泡通知能力（`QSystemTrayIcon.showMessage`），当前未使用 | `tray/tray.py`（`self._tray`） |
| 切换执行路径有三条，全部汇流 `ModelManager`：启动首载 `main._async_load_model → manager.load_initial`；托盘切换 `tray._on_switch_model → worker.submit_switch`；Socket 切换 `handlers/model_switch.py → worker.submit_switch` | `main.py`、`tray/tray.py`、`handlers/model_switch.py` |
| GGUF 条目下载涉及**两个仓库**（权重仓 + VAD 共享仓），现有缓存探测只查权重仓 | `models/loader.py::_load_funasr_gguf` |
| 客户端（Zen_VocoType_Client）无模型选择 UI，仅在 recognize 遇 2002 时提示「模型切换中」 | `Zen_VocoType_Client/src/.../app.py` |

### 已发现的相关问题（决策点，见 §6）

- **下载超时假象**：Socket 路径下 `submit_switch` 等待上限为 `infer_timeout_s`（默认 60s）。大模型首次下载必然超时，调用方收到 3002「模型切换超时」，但 worker 后台仍继续下载并最终切换成功——调用方与用户得到矛盾信息。托盘路径同理（临时线程内超时记 error 日志，下载仍在继续）。

## 3. 目标

1. 三条切换路径任一命中「目标模型未缓存」时，**统一点位**产生「未缓存，即将下载」事件；
2. 下载全程托盘可见：状态行/图标呈现「下载中：<模型名>」，并有气泡通知（开始下载 / 下载完成进入加载自检 / 下载失败含原因）；
3. headless（无托盘）降级为日志提醒，不缺失信息；
4. 不改动协议错误码、不改动 Socket 协议格式、核心层（state/manager/loader/worker）**零 Qt 依赖**。

## 4. 方案设计

### D1 缓存探测单一出处（新模块 `models/cache.py`）

将 `tray/models_dialog.py::cache_status` 的探测逻辑**下沉**为核心层纯函数，托盘展示层改为调用方（文案拼装留在展示层）：

```python
def is_model_cached(entry: ModelEntry, models_dir: Path) -> bool:
    """local_path 条目恒 True；model_id 条目按 modelscope 缓存布局探测。"""
```

覆盖分支（🔴 禁止只查权重仓就判定 GGUF 已缓存）：

- `local_path` 条目：恒为「已就位」；
- 普通 funasr / qwen3-asr 条目：探测 `<models_dir>/models/<org>--<name>`；
- `funasr-gguf` 条目：权重仓 + VAD 仓（`extra_params.vad_repo` 或默认 `GGUF_DEFAULT_VAD_REPO`）**两者都命中**才算已缓存；
- funasr 条目的 `vad_model_id` / `punc_model_id` 附属模型：纳入探测（同样会触发下载），任一缺失视为未缓存。

探测失败（目录不可读等 OSError）按「未缓存」处理并记 warning——🔴 禁止静默。

### D2 核心状态扩展：`ServiceState` 增加下载标记

`state.py` 新增（读写全部走既有 `_lock`，红线不变）：

- 字段：`_downloading_model: str | None`
- 方法：`mark_downloading(model_name)` / `clear_downloading()` / 属性 `downloading_model`

**打点位置在 `ModelManager`**（三条路径唯一汇流点，`load_initial` 与 `switch` 共用内部加载段）：

1. 加载前调 `is_model_cached`：未缓存 → `state.mark_downloading(name)` + `logger.info("模型 {} 未缓存，开始下载…")`；
2. 加载返回（成功或异常）→ `finally: state.clear_downloading()`；
3. 已缓存 → 不打点，行为与现状完全一致。

由此**启动首载、托盘切换、Socket 切换**自动全覆盖，无需在 main.py / handlers / tray 各打一份点。

### D3 托盘呈现（`tray/tray.py`）

- **持续状态**：`_refresh` 快照扩展为五元组 `(status, model, detail, switching, downloading)`；`downloading` 非空时：
  - 状态行：`状态：下载中…（<模型名>）`（模型名截断复用 `_truncate`）；
  - 图标沿用橙色 `TrayStatus.LOADING`（下载是加载的子阶段，不新增颜色语义）；
  - tooltip：`Zen_VocoType_Service — 下载中…`。
- **瞬时气泡**（`showMessage`， fire-and-forget，不阻塞轮询）：轮询检测到 `downloading` **由空转非空**的跳变时弹一次：
  - 标题 `模型下载`，正文 `模型 <名> 尚未缓存，正在从 ModelScope 下载，大模型可能耗时较长…`；
  - 下载结束后的「加载完成/切换成功」复用现有状态行绿色就绪即可，**不额外弹完成气泡**（决策点 2 已裁定）；
  - 下载失败走既有 ERROR 状态行（红 + 原因），已可见，不额外弹窗。
- `showMessage` 可用性依赖 `QSystemTrayIcon.supportsMessages()`，不支持时降级仅状态行，记 warning 一次（🔴 不静默）。

### D4 headless 降级

无托盘环境：D2 的 `logger.info` 已保证「开始下载」进日志；加载完成/失败日志 loader 层已有。无需新增代码，计划中验证即可。

### D5 协议与错误码

不改。下载期间 recognize 仍按现状 2002 拒绝（`switching` 标记在下载前已置位，语义自然覆盖下载全程）。

## 6. 决策裁定（2026-07-29 21:56 已确认）

1. **下载超时假象**（§2 末）：**选项 A——本期仅提醒，不动超时机制**。下载超 60s 后 Socket 调用方仍收 3002，但托盘「下载中…」状态持续可见，用户可等其完成。该已知行为记录于此，后续如需解耦（提交方轮询等待等）另立计划。
2. **完成气泡**：**不弹**。下载完成后仅状态行转绿「就绪」，不额外打扰。
3. **下载进度百分比**：**不做**。本期为「不确定态」提醒（仅下载中/完成/失败），后续如有需要再评估。

## 7. 红线与约束

- 🔴 核心层（state/manager/loader/worker/cache）零 Qt import——托盘轮询读状态，方向不可逆；
- 🔴 跨线程状态全部经 `ServiceState` 持锁读写，禁止散落裸变量；
- 🔴 探测/通知任何失败记日志，禁止静默；
- 🔴 不新增协议错误码、不改 Socket 协议；
- 托盘轮询快照变化才重绘的既有优化（稳态零绘制）不得破坏；
- 通知文案中文，与现有托盘文案风格一致。

## 8. 验收标准

1. 删除某模型缓存目录后，托盘点选该模型：立即弹「尚未缓存，正在下载」气泡，状态行显示「下载中…（模型名）」，图标橙色；
2. 下载完成后状态行转绿「就绪」，当前模型行更新；
3. 下载失败（断网）状态行转红并含真实原因；
4. 已缓存模型切换：全程无「下载中」字样、无气泡，行为与现状一致；
5. 启动首载未缓存默认模型：同样出现「下载中」状态与气泡；
6. headless 模式：日志含「未缓存，开始下载」记录；
7. 全部新增单测通过，既有测试无回归。
