> **范围**：全仓库 Git 历史（master 分支，含已删除但仍在历史中的文件）+ 当前工作区

> **方法**：只读审计（`git log` / `git grep` / `git rev-list --objects` / 全历史文件清单排查）；清洗经 `git filter-repo` 2.47.0

## 1. 结论摘要

**整体风险等级：低～中。无密钥、无录音、无日志等硬泄露。** 审计发现真正暴露的只有三样相互关联的信息：

1. **作者真实 Outlook 邮箱**（全部提交的作者/提交者字段）
2. **系统用户名**（全历史约 560 处用户家目录绝对路径，形如 `/home/<用户名>/...`）
3. **自建 Forgejo 实例的用户名线索**（仅存在于本地 `.git/config`，本就不入历史）

三者可相互串联到同一人。**应对方案：推送公开平台前完成历史清洗**（已实施，见 §6）。

## 3. 泄露面定性

暴露信息 = **一个真实邮箱 + 一个系统用户名 + 目录布局习惯**，不含密码、密钥、私人文件内容。按泄露场景分：

| 场景 | 风险 |
|:---|:---|
| 继续只放私有 Forgejo | 基本无风险，仅自己可见 |
| 推送至 GitHub 等公开平台 | 邮箱随每个提交暴露（可被垃圾邮件/钓鱼收割）；用户名与目录布局暴露攻击面信息，但敏感度有限 |

---

## 4. 清洗方案（已按此实施）

1. **作者/提交者邮箱改名**：全部提交统一替换为 GitHub noreply 邮箱（`--mailmap`）
2. **全历史文本替换**：用户家目录绝对路径 → `~`；旧署名英文 ID → `Samjossi`（`--replace-text`）
3. **保留** `llama-funasr-cli` 5.9MB vendor 二进制（合法 vendor，剔除会破坏历史自包含性）

工具：`git filter-repo`（文本替换 + 身份重写一次跑完）。

---

## 5. 遗留事项

- 提交信息（commit message）经核查不含敏感串，未做替换。
- `文档/提示语句/约束随机搜索方法论_在混沌解空间中寻路_v1.0.md` 中保留笔名「afro zen」，为既有署名风格，可由用户后续定夺是否再改。
- 历史重写后所有 commit hash 变更，`文档/修改记录/` 等文档中引用的旧 hash 失效（可接受副作用）。
- 实机用户配置 `~/.config/zen_vocotype/user_config.yaml` 中的本地路径属本机运行数据，不入库，无需处理。
